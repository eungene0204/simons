# nullStock 소프트웨어 공학 완성도 평가 · 2026-11-19

기준 커밋 `b00a4a94`. **도메인 오류를 검출하고 변경을 반복할 수 있는 수준이다. 운영 중인 서비스의 품질과 장애 복구 능력을 지속적으로 입증하는 단계는 부분 달성이다.** 정확성에 큰 영향을 주는 백테스트, 신규 버전 배포, 데이터 복구와 사용자의 실제 이용 경로를 우선 표본으로 삼았다. 아래의 강도는 이 프로젝트에 대한 판단이며 표준 인증 점수가 아니다.

## 우선순위와 완료 기준

1. **검증 커밋과 배포 커밋 일치.** 배포 작업은 승인된 SHA를 받아 체크아웃하는 대신 실행 시점의 origin/main을 가져온다. 다른 push가 끼면 검사 결과가 다른 소스에 연결될 수 있다. 워크플로가 받은 SHA나 그 SHA로 만든 이미지 digest를 배포하고 운영 버전과의 일치를 기계적으로 검증하면 닫힌다. 실제 오배포 여부는 미확인이다. [배포 명령](../../.github/workflows/ci.yml#L159)
2. **서비스가 동작해야 배포 성공.** 현재 흐름은 서버에서 빌드·마이그레이션·기동 후 컨테이너 목록을 출력한다. 마지막 검색 진단 실패는 허용한다. PR에서 운영 빌드를 검증하고, 배포 뒤 웹에서 한국 예시 전략 결과까지 읽는 합성 요청이 실패하면 릴리스가 실패하도록 한다. 직전 버전 복귀와 스키마 호환 여부도 같은 시나리오에서 확인한다. [배포 후 단계](../../.github/workflows/ci.yml#L201)
3. **복구 능력 실측.** 격리 환경에 앱 DB를 복원하고 전략·결과의 관계와 데이터 파일을 검증한다. 마지막 복구 가능 시각, 복구 소요 시간, 목표와의 차이를 남기면 백업 정책이 실제 서비스 복구로 연결된다. [데이터별 복구 정책](../deployment.md#10-백업)
4. **백테스트 성공률을 동일한 요청 집합에서 계산.** 서버의 승인 요청을 기준으로 완료·실패·시간 초과를 연결하고 최근 30일 분모, 누락 건수, 성공률과 p95를 보고한다. 대기·사용자 취소를 어떻게 셀지도 정의한다. [현재 집계의 제약](../KPI.md#6-품질-지표)
5. **연구 결과 재현성.** 고정한 KR 전략·가격·재무 입력·거래 비용·엔진 버전으로 저장된 거래 원장과 지표를 다시 계산한다. 데이터 개정 전 결과도 독립 환경에서 같은 허용 오차 안에 들어오는지가 완료 기준이다. [엔진 회귀](../../backend/tests/test_lookahead_no_prelisting_trades.py)


## 웹 접근성 표본

모달을 열 때 포커스를 옮기고, Tab과 Shift+Tab이 모달 안에서 순환하며, 닫은 뒤 호출 지점으로 복귀하는 것이 W3C의 모달 패턴이다. 프로젝트는 이 동작을 공통 훅과 UI 규칙으로 정의한다. [W3C 모달 패턴](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) · [프로젝트 키보드 계약](../UI_GUIDELINES.md#모달다이얼로그-키보드-계약)

공통 확인창의 확인·취소·Esc 동작은 `npm run test:frontend -- --run components/__tests__/ConfirmDialog.test.tsx` 실행에서 2건 통과했다. 저장된 검증 결과 모달에는 이름과 닫기 버튼이 있으나 컴포넌트가 공통 훅을 사용하지 않고 자체 포커스 순환이나 Esc 처리도 구현하지 않는다. 같은 지침의 적용 수준이 화면별로 다르다. 이 모달을 실제 브라우저에서 열어 첫 포커스, 양방향 순환, Esc와 원래 버튼으로의 복귀를 검사하면 사용자 영향을 판별할 수 있다. 전체 서비스의 WCAG 2.2 AA 적합성은 미검증이다. [확인창 테스트](../../components/__tests__/ConfirmDialog.test.tsx) · [저장된 검증 결과 모달](../../components/strategy/backtest/SavedValidationsModal.tsx) · [WCAG 2.2](https://www.w3.org/TR/WCAG22/)
