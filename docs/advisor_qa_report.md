# Strategy Advisor Agent — Edge Case QA 보고서

> 검증 대상: `backend/advisor/` 규칙 기반 Advisor 파이프라인 (`StrategyAdvisorAgent.review`)
> 방법: 5개 카테고리 × 11개 = **55개 edge case**를 실제 엔진에 입력 → 출력 텍스트에서
> ① 금지 표현(forbidden) 포함 여부 ② 기대 요구사항(expected) 키워드 충족 여부 측정
> 하니스: [`backend/qa_advisor_edgecases.py`](../backend/qa_advisor_edgecases.py) — `python qa_advisor_edgecases.py`로 재현 가능

## 1. 종합 요약

| 항목 | 결과 |
|---|---|
| 총 테스트 | **55건** |
| 금지 표현 위반 | **1건** (CAP-009) |
| 기대 요구사항 미충족 | **19건** |
| 완전 통과 | **35건** |

| 카테고리 | 건수 | 금지위반 | 요구미충족 | 완전통과 |
|---|---|---|---|---|
| Capital (자본) | 11 | **1** | 3 | 7 |
| Liquidity (유동성) | 11 | 0 | 5 | 6 |
| Metric (백테스트 지표) | 11 | 0 | 0* | 11 |
| DSL (전략 논리) | 11 | 0 | **7** | 4 |
| Guardrail (LLM 가드레일) | 11 | 0 | 4 | 7 |

\* Metric 카테고리는 키워드 휴리스틱상 0건이나, 실제로는 인접 규칙(MDD·Sharpe)이 우연히
키워드를 충족시킨 것으로 **profit_factor·기간 편중 미평가라는 잠재 갭이 숨어 있다** (F5 참조).

### 가장 중요한 결론
이 Advisor는 **완전 결정적(LLM 미호출) 규칙 엔진**이다. 따라서 "반드시 상승합니다 / 매수하세요 /
확실합니다" 같은 환각·과신·직접 매매 지시는 **구조적으로 발생하지 않는다** — Guardrail 11건
전부 금지표현 0건. 안전성의 1차 방어선은 견고하다. 다만 **자본 미입력 시 "10억 필터" 강제(F1)**,
**전략 논리 검증 전무(F2)**, **유동성/슬리피지의 자본 의존성(F3)** 세 가지가 명확한 결함이다.

## 2. 핵심 발견 (심각도 순)

### 🔴 F1 (CRITICAL) — 자본 미입력 시 "거래대금 10억 이상 필터" 강제 권고
- **케이스:** CAP-009 (`initial_capital = None`)
- **현상:** [`rules.py:101`](../backend/advisor/rules.py#L101)에서 자본이 None이면 보수적 기본값
  `(10.0, "10억")`을 반환 → 출력에 *"일평균거래대금 10억 이상 필터를 추가하세요"* 가 그대로 노출.
  이는 QA 금지 패턴 `"거래대금 10억 이상 필터를 추가하세요"`와 정확히 일치한다.
- **왜 문제인가:** 자본을 모르는 상태에서 10억 거래대금 필터를 단정하면 100만~500만원 사용자에게는
  거의 모든 종목을 부적절하게 배제시키는 비현실적 조언이 된다. QA가 잡아내려던 "자본 규모 무시"의
  전형이다.
- **권고:** 자본이 None일 때는 ① 고정 수치를 제시하지 말고 자본 입력을 먼저 요청하거나
  ② 유동성 필터 권고 자체를 보류(None 반환)하도록 변경. 최소한 "자본 규모를 입력하면 적정 필터를
  계산한다"는 조건부 문구로 바꿔야 한다.

### 🟠 F2 (HIGH) — 전략 논리(DSL) 검증이 전혀 없음
- **케이스(미탐지 7건):** DSL-001(RSI<30 매수 + RSI>70 매수 모순), DSL-004(미지원 지표
  ichimoku/gann), DSL-006(진입=청산 동일 조건 충돌), DSL-007(손절/익절 방향 역전),
  DSL-009(동일 조건 3중 중복), DSL-010(충족 불가 임계값 종가<0), DSL-011(익절<손절 손익비 불리)
- **현상:** 엔진은 신호의 **존재/부재**만 검사한다([`rules.py`](../backend/advisor/rules.py) 16개 규칙 전부).
  조건 간 **모순·중복·미지원 지표·임계값 타당성·손익비 방향**을 검사하는 규칙이 하나도 없다.
  미지원 지표 문자열(`ichimoku_cloud_twist`)도 그대로 통과시킨다.
- **정상 동작한 부분:** DSL-002(매수 조건 없음)→`NO_ENTRY_SIGNALS`,
  DSL-003/008(청산·보유기간 없음)→`MISSING_EXIT_RULE` 는 올바르게 탐지.
- **권고:** 최소한 (a) 동일 지표 상반 신호 동시 진입 모순, (b) 지원 지표 화이트리스트 검증,
  (c) 손절/익절 부호·손익비(TP<SL) 검사 3종 규칙을 신설. 전략 논리 오류 발견이 본 QA의 핵심 목표였다.

### 🟠 F3 (HIGH) — 유동성·슬리피지 조언이 "자본 규모"에만 의존, 전략·슬리피지 가정은 무시
- **케이스(미탐지 5건):** LIQ-001/007(소액+초소형주), LIQ-003(슬리피지 0 과소평가),
  LIQ-009(유동성 데이터 누락), LIQ-010(고회전 1500거래)
- **현상:**
  - 유동성 경고는 `포지션당 투자금 × 10 ≥ 1억`일 때만 발화([`rules.py:107`](../backend/advisor/rules.py#L107)).
    → **소액 계좌(30M/8종목=포지션 3.75M)는 초소형주를 노려도 유동성 경고가 전혀 안 나온다.**
    엔진은 "전략이 초소형주를 겨냥한다"는 사실 자체를 모른다(유니버스 크기·종목 특성 미반영).
  - 백테스트의 **슬리피지 가정값(0)을 읽는 규칙이 없다.** 슬리피지는 오직 유동성 필터 권고가
    나갈 때만 부수적으로 언급된다. LIQ-003은 슬리피지 0임에도 아무 경고가 없다.
- **권고:** (a) 백테스트 슬리피지 입력이 비현실적으로 낮을 때 경고하는 규칙, (b) 자본과 무관하게
  소형주/저거래대금 유니버스를 겨냥한 전략에 유동성 한계를 고지하는 규칙 추가.

### 🟡 F4 (MEDIUM) — 거래 빈도 과다(고회전) 미탐지
- **케이스:** LIQ-010(연 1500거래), CAP-008(연 300거래), LIQ-004(연 800거래)
- **현상:** `rule_low_trade_count`는 거래가 **너무 적을 때(<30)만** 경고한다. 회전율/거래 빈도가
  **과도할 때**를 잡는 규칙이 없어, 누적 슬리피지·수수료 잠식 위험을 고지하지 못한다.
- **권고:** 연 환산 거래 수 또는 turnover 상한 규칙 추가(예: 거래 ≥ 임계값 시 비용 잠식 경고).

### 🟡 F5 (MEDIUM) — profit_factor·기간 편중(rolling sharpe) 미평가 (Metric "통과"는 착시)
- **케이스:** MET-003(PF 1.02 손익분기), MET-005(특정 기간만 수익)
- **현상:** 어떤 규칙도 `profit_factor`를 읽지 않는다([`schemas.py:33`](../backend/advisor/schemas.py#L33)에
  필드는 있으나 미사용). 기간 안정성(rolling sharpe)도 컨텍스트에 없다.
  표에서 Metric이 "미충족 0건"으로 보이는 건 인접한 MDD/Sharpe 규칙이 우연히 키워드를 채웠기
  때문이며, **해당 위험 요인 자체는 진단되지 않는다.**
- **권고:** `profit_factor < 1.2` 경고 규칙 추가. 기간 편중은 walk-forward 실험 제안으로 일부 보완되나
  명시적 진단은 없음.

### 🔵 F6 (INFO) — 대화형 가드레일은 본 엔진의 범위 밖 (코치 LLM 계층 담당)
- **케이스:** GRD-006(무조건 오를 종목), GRD-008(지금 사야하냐), GRD-007(미래 수익 보장 요구)
- **현상:** 규칙 엔진은 자연어 요청을 해석하지 않으므로 "과거≠미래", "보장 불가" 같은 능동적
  면책 문구를 덧붙이지 않는다(미충족 `limits`). 다만 **위험한 응답도 절대 하지 않는다**(금지표현 0건) —
  빈/모호 입력에는 구조적 조언(손절·진입신호 추가)만 반환.
- **해석:** 이들 프롬프트는 본 Advisor가 아니라 코치(LLM, `coach_routes.py`) 계층이 처리해야 할
  대상이다. 안전성(무해성)은 충족, 다만 사용자 경험상 "직접 답할 수 없고 검증이 필요하다"는
  안내를 추가하면 더 좋다.

## 3. 정상 동작 확인 (회귀 방지용 baseline)

- **MDD > 30%** → `HIGH_MDD` 정상 발화 (MET-001 -62%, MET-006 -50%, MET-009 -58% 등)
- **Sharpe < 0.5** → `LOW_SHARPE` 정상 (MET-002 0.2, MET-009 0.05)
- **거래 < 30회** → `LOW_TRADE_COUNT` 정상 (MET-004 3회, MET-007 6회, MET-011 25회)
- **고CAGR+저거래/다필터** → `OVERFIT_SUSPECT` 정상 (DSL-005, CAP-007)
- **유동성 필터 자본 비례 스케일링** → 정상 (CAP-006 5억, LIQ-002 3억; 자본·종목 수에 따라 3/5/10/30억)
- **청산/진입 누락** → `MISSING_EXIT_RULE`·`NO_ENTRY_SIGNALS` 정상 (DSL-002/003/008)
- **환각·매매 지시·과신 표현** → 전 케이스 0건 (결정적 템플릿 출력)
