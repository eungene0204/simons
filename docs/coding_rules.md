# 코드 설계 원칙

코드를 작성하거나 수정할 때 반드시 아래 원칙들을 준수한다.

## SOLID — 객체 지향 5대 원칙
- **단일 책임 (SRP)**: 하나의 클래스/함수는 하나의 역할만 담당한다
- **개방-폐쇄 (OCP)**: 확장에는 열려 있고, 수정에는 닫혀 있어야 한다
- **리스코프 치환 (LSP)**: 하위 타입은 상위 타입을 대체할 수 있어야 한다
- **인터페이스 분리 (ISP)**: 사용하지 않는 인터페이스에 의존하지 않는다
- **의존 역전 (DIP)**: 구체 구현이 아닌 추상에 의존한다

## DRY — Don't Repeat Yourself
코드와 로직을 중복하지 않는다. 같은 로직이 두 곳 이상 등장하면 추출하여 재사용한다.

## KISS — Keep It Simple, Stupid
단순하게 유지한다. 과도한 추상화, 불필요한 패턴 도입을 지양한다.

## YAGNI — You Ain't Gonna Need It
지금 당장 필요하지 않은 기능은 만들지 않는다. 미래를 위한 코드는 작성하지 않는다.

## SoC — Separation of Concerns
관심사를 명확히 분리한다. 데이터 로딩, 비즈니스 로직, UI 렌더링은 각각 독립된 레이어에서 처리한다.

## LoD — Law of Demeter
객체는 직접 아는 객체하고만 대화한다. `a.b.c.method()` 같은 깊은 체이닝을 피한다.

## Composition Over Inheritance
상속보다 합성을 우선한다. 유연한 코드 재사용을 위해 조합 가능한 작은 단위로 설계한다.

## Boy Scout Rule
코드를 수정할 때마다 건드린 부분 주변을 이전보다 조금 더 깨끗하게 남긴다.

## Fail Fast
오류는 발생 즉시 감지하고 중단한다. 잘못된 입력이나 상태는 최대한 일찍 검증하여 문제가 전파되지 않도록 한다.
