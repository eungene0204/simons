## 이 문서의 역할

이 문서는 **무엇을, 누구를 위해, 왜 만드는지**와 **어디까지 만드는지**를 정한다.
시스템이 정확히 어떻게 동작해야 하는지(입력·출력·예외·수치 규칙)는 [SRS](SRS.md)가 정본이다.
이 문서의 기능 설명은 사용자 관점의 요약이고, 세부는 각 항목의 SRS 링크를 따른다.
두 문서가 충돌하면 동작은 SRS를, 방향·우선순위·범위는 이 문서를 따른다.

## 1. 배경과 문제

국내 개인 투자자는 유튜브·책·커뮤니티에서 전략을 많이 접하지만, 그 전략이 과거에 실제로 통했는지 확인할 수단이 거의 없다.

| 문제 | 지금 사용자가 겪는 일 |
|---|---|
| 검증 수단이 없다 | "골든크로스면 오른다", "저PER이 답이다" 같은 말을 믿거나 말거나로 매매한다 |
| 검증하려면 코딩이 필요하다 | 퀀트 책을 읽고 백테스트를 하려다 파이썬 단계에서 포기한다 |
| 기존 퀀트 도구는 문법을 배워야 한다 | 조건식 입력 방식을 익히는 비용이 크고, 데이터의 생존편향 여부도 알기 어렵다 |
| 시장에 넘치는 것은 추천이다 | 종목 추천·리딩방 서비스가 많고, 사용자는 그 피해 사례를 반복해서 접한다 |

## 2. 제품 정의

**널스탁은 사용자가 말로 설명한 투자 전략을 과거 데이터로 시뮬레이션해 주는 투자 연구·백테스트 플랫폼이다.**
흐름은 **설계 → 검증 → 최적화 → 가상계좌 시뮬레이션**이다.

- 한 문장 포지셔닝: "아무도 당신에게 종목을 찍어주지 않습니다. 당신의 가설을 검증해 드립니다."
- 핵심 차별점
  1. **자연어 전략 설계**: 코딩이나 조건식 문법 없이 문장으로 전략을 만든다.
  2. **편향을 줄인 데이터**: 상장폐지 종목을 포함한 시점별 유니버스(PIT)로 생존편향을 줄인다.
  3. **과최적화 점검 도구**: 워크포워드·몬테카를로·비용 민감도 같은 검증을 한 화면 흐름 안에서 실행한다.
  4. **추천하지 않는다는 것 자체가 신뢰 요소**다. 디스클레이머는 숨기지 않고 드러낸다.

### 2.1 우리가 하지 않는 것 (규제 안전 원칙)

널스탁은 유사투자자문업에 해당하는 기능을 제공하지 않는다. 이 원칙은 모든 기능·문구·지표에 우선한다.
상세 금지 목록은 [CLAUDE.md 규제 안전 원칙](../CLAUDE.md)과 [SRS §8.2](SRS.md#82-법적규제-제약)를 따른다.

| 하지 않는 것 | 예 |
|---|---|
| 추천 | 종목·전략·섹터·ETF·포트폴리오 추천, "이 전략을 추천합니다" |
| 전망 | 시장 예측, 매수·매도 시점 제안, "지금 사기 좋은 시기입니다" |
| 맞춤 조언 | 나이·자산·소득·위험 성향 기반 제안 |
| 우열 판단·자동 개선 | "전략 B가 더 우수합니다", "전략 B로 바꾸세요" |

허용되는 것은 **계산, 백테스트, 시뮬레이션, 과거 데이터의 객관적 표시**다.

## 3. 대상 사용자

우선순위는 A > B > C다. 근거는 [마케팅 전략 §2](marketing_plan.md)를 따른다.

| 세그먼트 | 누구 | 핵심 불편 | 널스탁이 주는 것 | 핵심 메시지 |
|---|---|---|---|---|
| **A. 퀀트 입문자** (최우선) | 퀀트 책·영상을 봤지만 코딩을 못 하는 20~40대 직장인 투자자 | 백테스트 단계에서 이탈 | 문장 하나로 전략 생성과 백테스트 | "말로 하면 백테스트가 됩니다" |
| **B. 검증하고 싶은 일반 투자자** | 들은 전략의 진위가 궁금한 능동적 개인 투자자 | 확인할 방법이 없음 | 통념을 10년치 데이터로 바로 확인 | "그 말, 지난 10년 데이터로 확인해 보세요" |
| **C. 기존 퀀트 도구 사용자** | 다른 퀀트 도구 사용자 또는 이탈자 | 문법 학습 비용, 생존편향 의심, 검증 기능 부족 | PIT 유니버스, 워크포워드·몬테카를로, 자연어 입력 | "생존편향 없는 데이터로, 과최적화까지 검증" |

### 3.1 페르소나 (디자인 참고용)

- **지훈 (A, 32세, 회사원)**: 퇴근 후 휴대폰으로 퀀트 영상을 본다. 영상에서 본 "PER 낮고 ROE 높은 종목"을 그대로 입력해 결과를 보고 싶다. 용어는 반쯤 안다. 화면이 복잡하면 바로 닫는다.
- **수진 (B, 45세, 자영업)**: 커뮤니티에서 "RSI 30 밑이면 산다"는 글을 봤다. 맞는 말인지 궁금하다. 결과 숫자보다 "그래서 과거에 어땠는지"를 쉬운 말로 알고 싶다.
- **민석 (C, 38세, 개발자)**: 다른 퀀트 도구를 2년 썼다. 데이터 처리 방식(수정주가, 상장폐지, 체결 시점)을 먼저 확인하고, 거래 비용·워크포워드 결과를 꼼꼼히 본다.

## 4. 핵심 사용자 여정

```
방문 → 첫 전략 입력 → (되묻기 답변) → 첫 백테스트 완주(가치 경험) → 검증·수정 반복
     → 저장 → 재방문 → 월 한도 소진 → 유료 전환 → (선택) 가상계좌로 실시간 시뮬레이션
```

| 단계 | 사용자 목표 | 제품이 해야 할 일 | 실패하면 생기는 일 |
|---|---|---|---|
| 첫 전략 입력 | 머릿속 전략을 적는다 | 예시 카드와 입력창을 바로 보여 준다 | 무엇을 써야 할지 몰라 이탈 |
| 되묻기 | 빠진 값을 채운다 | 빠진 값만 하나씩 묻고, 고를 수 있는 칩을 준다. 말하지 않은 값을 몰래 정하지 않는다 | 엉뚱한 전략이 실행되거나 같은 질문이 반복됨 |
| 전략 요약 확인 | 내 말이 맞게 이해됐는지 본다 | 해석된 조건을 사람이 읽는 말로 카드에 보여 준다 | 틀린 전략으로 백테스트하고도 모름 |
| 첫 백테스트 완주 | 결과를 본다 | 진행 상황을 보여 주고, 결과를 과거 사실의 언어로 표시한다 | 기다리다 이탈, 결과를 전망으로 오해 |
| 검증·수정 | 결과를 의심하고 바꿔 본다 | 대화로 조건을 수정하고 검증 도구를 실행한다 | 한 번 보고 끝, 재방문 이유 없음 |
| 저장·재방문 | 나중에 다시 본다 | 전략·버전·백테스트 기록을 보관한다 | 매번 처음부터 다시 입력 |
| 유료 전환 | 더 많이 실험한다 | 한도와 플랜 차이를 명확히 보여 준다 | 한도에 막혀 이탈 |

## 5. 기능 요구사항

우선순위 정의
- **P0**: 핵심 여정(입력 → 해석 → 백테스트 → 결과)에 필수. 이것이 깨지면 제품 가치가 없다.
- **P1**: 재방문·유료 전환을 만드는 기능.
- **P2**: 고급 사용자·확장 기능.

> 우선순위는 이 초안의 제안이다. 확정은 [§9 열린 질문](#9-열린-질문)을 따른다.

### 5.1 전략연구소 — 자연어 전략 설계 `P0`

**사용자 가치**: 코딩 없이 문장으로 전략을 만든다.

- 사용자는 전략을 문장으로 입력한다. 예: "코스피200에서 PER 10 이하, RSI 30 아래면 사고 10% 오르면 팔아줘"
- 시스템은 문장을 해석해 **전략 요약 카드**(유니버스·매수 조건·매도 조건·리밸런싱·위험 관리·기간)로 보여 준다.
- 값이 빠졌으면 **되묻는다**. 사용자가 말하지 않은 값을 기본값으로 몰래 확정하지 않는다.
- 엔진이 지원하지 않는 개념은 숨기지 않고 "반영하지 못한 부분"으로 안내한다. 비슷한 지표로 대신 반영했으면 그 사실도 알린다.
- 이미 만든 전략은 대화로 고친다. 예: "손절은 7%로 바꿔줘"
- 예시 카드(국내·미국)를 눌러 바로 시작할 수 있다.
- 지난 대화는 왼쪽 대화 기록에서 다시 연다.
- 전략 추천이나 종목 판단을 요구하면 판단하지 않고 전략 만들기로 안내한다.

**디자인 메모**
- 선택지 칩이 떠 있는 동안에는 입력창을 숨겨, 지금 무엇을 답해야 하는지 하나만 보이게 한다.
- 카드에 내부 식별자(`ocf_growth` 같은 값)가 그대로 노출되면 결함이다. 모든 항목은 사람이 읽는 라벨로 보여야 한다.
- 해석 진행 중에는 단계별 진행 상태를 보여 준다.

**성공 기준**: 입력한 문장이 되묻기 또는 전략 카드로 이어지고, 조건이 말없이 사라지지 않는다.
**상세**: [SRS §3.1.1](SRS.md#311-자연어-프롬프트-기반-전략-생성) · [§3.1.2 지원 지표](SRS.md#312-지원-시그널지표) · [§3.6b 종목 질문 전환](SRS.md#36b-종목-질문-의도-분류전략-전환-구-stock-analysis-agent) · [자연어 해석 계약](nl_interpretation_contract.md)

### 5.2 백테스트 실행과 결과 `P0`

**사용자 가치**: 내 전략이 과거에 어떻게 움직였는지 숫자와 그래프로 본다.

- 지원 범위: 기술 지표, 재무 지표, 순위(랭킹) 선택, 업종·테마 유니버스, 손절·익절·트레일링 스탑, 리밸런싱 주기, 수수료·슬리피지, 적립식 납입.
- 데이터 원칙: 상장폐지 종목을 포함한 시점별 유니버스, 수정주가, 거래정지 반영, 미래 정보 사용 금지.
- 실행 중에는 진행 상태를 실시간으로 보여 주고 취소할 수 있다.
- 결과 화면: CAGR, MDD, 샤프 비율, Profit Factor, 승률, 거래 통계, 수익곡선, 벤치마크 비교, 월별·연별 수익, 매매 기록(매매 사유 포함), CSV/JSON 다운로드.
- 모든 결과에 "과거 데이터 기반 시뮬레이션이며 미래 수익을 보장하지 않는다"를 표시한다.

**디자인 메모**
- 수익·손실 색상, 지표 색상 규칙은 [UI 가이드라인 §2](UI_GUIDELINES.md)를 따른다.
- 문구는 과거 사실로만 쓴다. "우수", "위험", "추천" 같은 평가어를 쓰지 않는다.
- 거래가 0건이면 빈 그래프 대신 왜 0건인지 설명한다.

**상세**: [SRS §3.2 백테스트 엔진](SRS.md#32-백테스트-엔진)

### 5.3 전략 검증 도구 `P1`

**사용자 가치**: 결과가 우연이나 과최적화가 아닌지 점검한다.

- 워크포워드 분석(학습 구간과 검증 구간을 나눠 반복)
- 몬테카를로 시뮬레이션(거래 순서를 섞어 결과 분포 확인)
- 거래 비용 민감도, 시작일 이동 점검
- 검증 결과 저장과 다시 보기
- 전략 검증 리포트(AI 서술, 유료 플랜): 결과가 왜 나왔는지, 무엇을 아직 믿으면 안 되는지, 다음에 무엇을 검증할지를 설명한다. 매수·매도 시점이나 구체적 조건 값은 제안하지 않는다.

**상세**: [SRS §3.2.3~](SRS.md#323-성능-메트릭) · FR-BT-022(검증 리포트) · FR-BT-049(워크포워드)

### 5.4 최적화와 일괄 테스트 `P2`

- 파라미터 최적화(Optuna): 사용자가 고른 파라미터 범위를 탐색하고 결과를 보여 준다. 결과는 과거 구간 기준이며 과최적화 위험을 함께 표시한다.
- 모두 테스트: 여러 전략을 한 번에 백테스트하고 결과를 나란히 본다. 정렬은 사용자가 고른 기준을 따르며, "최고의 전략" 같은 순위 문구를 쓰지 않는다.

**상세**: [SRS §3.3.3](SRS.md#333-전략-최적화-optuna) · [§3.1.5](SRS.md#315-독립형-배치-테스트)

### 5.5 내 전략·기록 `P1`

- 전략 저장(플랜별 개수 한도), 저장할 때마다 버전 기록, 이전 버전으로 되돌리기
- 백테스트 기록 목록과 다시 열기
- 전략 비교(Strategy Lab)

**상세**: [SRS §3.1.4](SRS.md#314-전략-저장-및-관리) · [§3.2.4](SRS.md#324-백테스트-이력-관리) · FR-STR-080(버전 이력)

### 5.6 스크리너 `P2`

- 저장한 전략의 매수 조건을 오늘 데이터에 적용해 조건을 만족하는 종목을 표로 보여 준다.
- 화면에 "사용자가 설정한 조건의 계산 결과이며 투자 추천이 아니다"를 표시한다.

**상세**: FR-RES-010

### 5.7 가상계좌 (모의투자) `P1`

**사용자 가치**: 백테스트한 전략을 실시간 시장 데이터로 돈 없이 굴려 본다.

- 플랜별 계좌당 초기 투자금으로 가상계좌 생성(실제 돈 아님)
- 수동 주문, 전략 연결 자동매매, 정액 적립식
- 포지션·주문·거래 내역 조회, 상장폐지 처리 정책 선택
- "자산·충전·포인트·리워드" 같은 금전 연상 표현을 쓰지 않는다(FR-PLAN-009).

**상세**: [SRS §3.4 가상 매매 시스템](SRS.md#34-가상-매매-시스템)

### 5.8 리서치 에이전트 `P2` (Premium)

- 후보 전략 생성 → 사전 선별 → 견고성 검증 → 최적화 → 잠금 구간 검증을 자동으로 실행하고 진행 상황을 보여 준다.
- 가상계좌 연결은 사용자가 직접 시작해야 한다.

**상세**: [SRS §3.4b](SRS.md#34b-strategy-research-agent-premium)

### 5.9 시장·종목 정보 `P2`

- 시장 지수, 종목 검색, 종목 상세(차트·종목정보·뉴스·공시), 관심 종목
- 객관적 데이터 표시만 한다. 종목 평가·전망을 붙이지 않는다.

**상세**: [SRS §3.7](SRS.md#37-시장-데이터-및-분석) · [§3.5.3](SRS.md#353-관심-종목) · [§3.6](SRS.md#36-뉴스-impact-ai-agent)

## 6. 전 기능 공통 요구사항

### 6.1 문구 (개발·디자인 공통)

| 쓴다 | 쓰지 않는다 |
|---|---|
| "과거 데이터 기준 CAGR은 12.4%였습니다" | "높은 성과가 기대됩니다" |
| "최대 낙폭은 -18%였습니다" | "좋은 전략입니다", "추천 전략" |
| "결과는 과거 데이터 기반 시뮬레이션입니다" | "앞으로도 잘 작동할 것입니다" |
| 전략 연구소, 백테스트 플랫폼, 사용자 생성 전략 | AI 투자 코치, 추천 전략 TOP 10, 수익률 보장 |

- 공개 목록의 기본 정렬은 최신순·조회순이다. 수익률 순은 사용자가 직접 고를 때만 쓴다.
- 브랜드는 **널스탁**이다. 사용자 화면에 내부 코드명을 노출하지 않는다.

### 6.2 자연어 해석 원칙

- 문장의 의미 해석은 LLM이 하고, 규칙 코드는 LLM 출력의 형식만 검증한다.
- 사용자가 말하지 않은 값은 묻거나, 제안 후 확인받는다.
- 상세: [자연어 해석 계약](nl_interpretation_contract.md)

### 6.3 디자인

- [UI 가이드라인](UI_GUIDELINES.md)을 따른다(따뜻한 다크 팔레트, 강조색 하나, WCAG AA 대비, 큰 제목은 세리프).
- 휴대폰 폭에서도 핵심 여정(입력 → 결과)이 끊기지 않아야 한다.
- 한국 화면은 한국어, /us 화면은 영어로만 표시한다.

### 6.4 비기능 요약

성능·신뢰성·보안·관측성의 수치 기준은 [SRS §4](SRS.md#4-비기능-요구사항)를 따른다. 제품 관점의 최소선은 다음과 같다.

- 같은 전략과 같은 데이터면 같은 결과가 나와야 한다(캐시·병렬 처리로 결과가 바뀌면 결함).
- 긴 작업(백테스트·검증)은 진행 상태를 보여 주고 취소할 수 있어야 한다.
- 사용자 개인정보와 투자 기록을 외부 분석 도구로 보내지 않는다.

## 8. 성공 지표

성공 지표의 정의·측정 방법·목표는 [KPI 문서](KPI.md)가 정본이다.

- **북극성 지표**: 주간 첫 백테스트 완주 사용자 수
- 보조 지표: 첫 백테스트 완주율, 7일 재방문율, 유료 전환율, 전략 해석 성공률
- 가드레일: 규제 금지 표현 노출 0건

사용자 전략의 수익률은 제품 성공 지표로 쓰지 않는다. 쓰면 높은 수익률 전략을 노출하도록 제품이 기울고, 이는 사실상 추천이 된다.
