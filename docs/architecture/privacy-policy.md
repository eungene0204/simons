# nullStock Privacy Policy Draft

> 검토 기준일: 2026-07-08
> 문서 상태: 운영 전 법무 검토용 초안
> 적용 서비스: nullStock 투자 연구 및 시뮬레이션 플랫폼
> 배포본: `components/landing/PrivacyPolicyPage.tsx` (이 문서의 초안과 조항 구조·내용을 동일하게 유지한다)

이 문서는 널스페이스가 제공하는 nullStock 서비스 개인정보처리방침 초안이다. 실제 배포 전 개인정보 보호책임자, 고객센터, 실제 수탁사 명칭과 이전 국가, 결제대행사 정보는 운영 환경과 법무 검토 결과에 맞게 확정해야 한다.

## 2. 서비스의 실제 개인정보 처리 현황 (작성 근거)

| 처리 | 실제 구현 | 방침 반영 |
|------|-----------|-----------|
| 회원가입 | Supabase Google OAuth 단일 경로(`lib/firebase.ts`는 실제로 Supabase 클라이언트, UI는 Google 로그인만 노출). 회사 DB의 `User.password`는 OAuth 계정에 대해 무작위 더미값이며 실제 이용자 비밀번호가 아님. 이메일/비밀번호 라우트(`app/api/register`, `/register`)는 UI 미연결 고아 코드로 라이브 미사용 | 제2조 Google 로그인만 기재, 비밀번호 미저장 명시 |
| 세션 | 회사 발급 JWT를 브라우저 httpOnly 쿠키로만 발급(stateless, `lib/auth.ts` `jwt.sign`). 서버/DB에 세션·토큰 테이블 없음 → 회사가 저장하지 않음 | 제7조(쿠키·세션 사용, 서버 미보관 명시). 제2조 자동 생성 정보에서는 제외 |
| 서비스 데이터 | 전략, 백테스트 이력, 저장된 검증 결과, 관심종목, 가상계좌 주문·체결 기록 (SQLite/Prisma) | 제2조·제4조 |
| 플랜·사용량 | `User.planTier`, `backtestCountThisMonth`, `lastLoginAt` 저장 | 제2조 자동 생성 정보·플랜 및 사용량 정보 |
| AI 처리 | 전략연구소 대화·종목 질문 텍스트가 프로덕션에서 Modal(미국) 호스팅 LLM으로 전송되어 응답 생성 | 제6조 국외 이전(AI 연산 인프라), 제11조 학습 미사용 약속 |
| 호스팅 | Vultr 단일 박스(앱+DB) | 제6조 클라우드 호스팅 수탁 |
| 결제 | 미도입 (플랜 구조만 존재) | 제6조 도입 시 결제대행사 처리 원칙만 기재 |

### 미구현 → 방침에서 제외한 항목 (2026-07-08 감사)

방침 초안이 실제 구현보다 넓게 서술했던 부분을 코드 대조 후 제거했다. 아래 기능을 실제로 구현하면 방침에 다시 반영해야 한다.

| 방침에서 뺀 서술 | 코드 근거(미구현) | 구현 시 복원 위치 |
|------|------|------|
| IP 주소·브라우저/기기 정보 수집 | 일반 이용자 IP·UA 저장 없음. IP는 `AdminAuditLog.ip`(관리자 작업)만 기록 | 제2조 자동 생성 정보 |
| 문의 내용·답변 이력·공지 수신 여부 | 문의/고객센터/공지 모델 없음 | 제2조, 제3조 |
| 접속 로그 3개월 보관(통신비밀보호법) | 접속 로그 저장 테이블 없음. `lastLoginAt`만 존재 | 제4조 |
| 쿠키 기반 이용 통계 산출·집계 분석 | analytics(GA·mixpanel 등) 파이프라인 없음 | 제3조, 제7조 |
| "서비스 내 계정 기능"으로 계정 삭제 | 사용자용 회원 탈퇴 엔드포인트·UI 없음(`deleteAccount`는 가상계좌용). status=DELETED는 관리자만 | 제8조 |

## 3. 개인정보처리방침 초안

조항 전문은 배포본 `components/landing/PrivacyPolicyPage.tsx`와 동일하게 유지한다. 조항 구성:

1. 제1조 (목적) — 개인정보 보호법 제30조에 따른 처리방침 수립·공개 취지 명시(SaaS 투자 연구 도구·금융 조언 미제공 설명은 히어로 문단으로 이동)
2. 제2조 (처리하는 개인정보 항목) — 회원가입·로그인(Supabase Google OAuth, 비밀번호 미수집·미저장 명시) / 서비스 이용 정보(AI 대화 입력 포함) / 자동 생성 정보(최근 로그인 시각·오류/보안 로그) / 플랜 및 사용량 정보
3. 제3조 (개인정보의 처리 목적)
4. 제4조 (보유 및 이용 기간) — 오류·보안 로그 제한 기간 보관, 전자상거래 기록 5년/5년/3년(유료서비스 도입 시)
5. 제5조 (제3자 제공) — 원칙적 미제공
6. 제6조 (처리 위탁 및 국외 이전) — 인증(Supabase, 미국 등)·호스팅·AI 연산(미국 등)·결제(도입 시), 거부 방법과 이용 제한 고지
7. 제7조 (쿠키와 세션 정보)
8. 제8조 (이용자의 권리와 행사 방법) — 만 14세 미만 가입 불허(이용약관 제4조와 정합)
9. 제9조 (개인정보의 파기)
10. 제10조 (안전성 확보 조치) — 비밀번호 해시, 전송 암호화, 접근 통제
11. 제11조 (자동화된 의사결정 및 AI 기능) — 입력 텍스트는 응답 생성에만 사용, 별도 동의 없이 모델 학습에 미사용
12. 제12조 (방침의 변경) — 시행일 2026-07-08

> 2026-07-08 결정: "개인정보 보호책임자 및 권익침해 구제" 조항은 보호책임자를 아직 지정하지 않은 단계라 방침에서 제외했다. 다만 개인정보 보호법 제30조·제31조는 처리방침에 보호책임자 성명·연락처를 기재하고 이를 지정할 것을 요구하므로, **유료서비스 오픈 등 실제 운영 전에는 이 조항을 반드시 복원**해야 한다.

## 4. 배포 전 확정 필요 사항

- 개인정보 보호책임자 지정 및 처리방침 조항 복원(성명·연락처, 권익침해 구제 안내 118/1833-6972/1301/182 포함) — 법정 필수 기재사항
- 고객센터 채널
- 수탁사 확정 명단: Supabase(리전 포함), 호스팅 사업자(Vultr 리전), AI 연산 인프라(Modal, 미국) — 국외 이전 고지에 국가명을 모두 기재해야 함(클라우드 복수 국가 시 전부)
- 결제대행사 선정 시 수탁 내역 추가
- 오류·보안 로그 실제 보관 기간과 파기 절차 확정(방침은 "제한된 기간"으로만 서술) — 접속 로그를 수집하기로 하면 제2조·제4조에 IP·보관기간 복원
- AI 입력 텍스트의 로그 보관 기간(백엔드 로그에 대화가 남는지) 점검 — 방침의 "응답 생성 즉시 처리 목적" 서술과 일치해야 함
- 사용자용 회원 탈퇴(계정 삭제) 기능 구현 여부 결정 — 구현하면 제8조에 "서비스 내 계정 기능" 복원. 미구현 상태에서는 고객센터 채널로만 처리
- 고객센터·문의 접수 채널 구축 시 제2조(문의 내용·답변 이력)·제3조 복원

## 5. 운영 가드레일

- 방침·UI·고객센터 답변에서 개인정보 수집 항목을 실제 구현보다 좁게 서술하지 않는다(이메일 가입 경로 누락 금지).
- 새 수탁사·외부 API(데이터 제공자, LLM 등)에 개인정보 또는 이용자 입력 텍스트를 전송하게 되면 제6조를 먼저 갱신한 뒤 배포한다.
- 이용자 대화·전략 텍스트를 모델 학습에 사용하려면 방침 개정과 별도 동의 절차가 선행되어야 한다.
- 가상계좌 데이터는 금전 정보가 아니지만 이용자의 연구 데이터이므로 접근 통제 대상으로 다룬다.
