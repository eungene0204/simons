## 발견 결함 목록 (심각도순)

### BF-01 [High/State Machine] "됐어"·"그만"이 취소로 오인되어 빌더 상태 전체 소실
- 입력: `됐어, 손절 10%로 해줘` / `이제 됐어 백테스트 돌려줘` / `그만 물어보고 그냥 진행해`
- 기대: 진행 의사로 해석(특히 값이 함께 있으면 값 반영)
- 실제: `_CANCEL_RE`(`그만|됐어`)가 매칭 → status=exited, **수집한 모든 필드 소실**
- 재현: `sb.step(state, "됐어, 손절 10%로 해줘")`
- 원인: `detect_control()`이 문장 의미와 무관하게 부분 문자열 매칭. 필드 파싱보다 먼저 실행됨
- 수정안: 취소어와 전략 값(%·필드 키워드)이 공존하면 취소로 보지 않기. "그만 물어보"처럼 뒤에 진행 동사가 오면 제외. 취소 시 즉시 소실 대신 "취소할까요?" 1회 확인

### BF-02 [High/State Machine] "취소하지 말고 계속해"도 취소됨
- BF-01과 동일 근원(부정 표현 미처리). `취소` 부분 문자열만 보고 종료

### BF-03 [High/Slot Filling] 용어 질문이 전략 유형을 조용히 확정 — "볼린저가 뭐야?" → 볼린저 전략 선택
- 입력: 전략 유형 질문 단계에서 `볼린저가 뭐야?` / `스토캐스틱이 뭐야?`
- 실제: 글로서리(`_BUILDER_GLOSSARY`)에 볼린저·스토캐스틱 항목이 없어 정의 답변 대신 `_parse_strategy_type`이 유형으로 인식·확정. 볼린저/스토캐스틱은 파라미터 스텝이 없어 **질문 두 단계를 건너뛰고 필터 단계로 점프**
- 원인: 글로서리 커버리지(13항목)와 유형 어휘(12유형)의 비대칭. 정의 마커 감지 시에도 미커버 용어는 필드 파싱으로 낙하
- 수정안: `_DEFINITION_MARKER_RE` 매칭 시 필드 파싱을 건너뛰고(상태 불변) 글로서리 미커버 용어는 "설명은 어려우니 …" 폴백 답변. 글로서리에 볼린저·스토캐스틱·CCI·PER 추가

### BF-04 [Medium/Slot Filling] "PER이 뭐야?"·"CCI가 뭐야?" — 정의도 없이 같은 질문만 반복(막다른 길)
- BF-03의 다른 갈래: 유형 어휘에도 안 걸리는 용어(PER)는 아무 일도 없이 동일 질문 재출력

### BF-05 [High/State Machine] 이미 채워진 필드의 정정 요청을 조용히 무시
- 입력: (universe=KOSPI 확정 후) `코스닥으로 바꿔줘` / `모멘텀 말고 골든크로스로 바꿔줘`
- 실제: `parse_input`이 `not state.universe`/`not state.strategy_type` 조건으로 스킵 → **아무 언급 없이** 다음 질문 반복
- 원인: 정정(修正) 경로 부재 — 최초 1회만 채우는 설계
- 수정안: 이미 채워진 필드와 다른 값 + 변경 동사(`바꿔|말고|변경|아니`) 감지 시 "○○로 변경할까요?" 확인 후 반영. 최소한 "이미 코스피로 설정되어 있어요. 변경하려면 '처음부터'라고 말씀해 주세요" 안내

### BF-06 [High/Parameter Parsing] 정정 표현 "3개월 말고 6개월" → 3개월로 오파싱
- `_MONTHS_RE.search`가 첫 매치(버려진 값)를 채택. 메인 NL 파서에는 red-flag(정정→None) 가드가 있으나 빌더에는 없음
- 수정안: `말고|아니라|대신` 뒤쪽 값을 우선하는 전처리(또는 빌더에도 red-flag 되묻기)

### BF-07 [High/Parameter Parsing] 가치 전략에서 방향 무시 — "PBR 5 이상 ROE 3 이하" → PBR≤5·ROE≥3
- 빌더 value 파서가 숫자만 뽑고 비교 방향은 고정(`<=`/`>=`) → 사용자 의도와 정반대 스크리닝을 조용히 생성
- 수정안: `이상|초과` 동반 PBR / `이하|미만` 동반 ROE 감지 시 "빌더는 저평가(PBR 낮음·ROE 높음) 기준만 지원해요" 안내 후 되묻기

### BF-08 [High→Medium/Validation] 손절 0%·200%가 "청산 조건 필수" 게이트를 통과한 뒤 조용히 제거됨
- 빌더는 `손절 0%`·`손절 200%`를 수락(risk_done=True)하고 confirmed → 이후 `enforce_strategy_minimums`가 값을 **드롭**(notices 안내는 있음) → 유일한 청산 조건이 사라진 전략이 확정됨
- 검증 agent가 최종적으로 no-exit을 잡아주므로 Critical은 아니나, "필수" 게이트가 무력화되고 사용자는 두 단계 뒤에야 문제를 알게 됨
- 수정안: `_parse_risk`에서 0<pct<100 범위 검증, 범위 밖이면 즉시 되묻기

### BF-09 [Medium/Validation] RSI 과매수 150 수락 — 발생 불가능한 청산 조건
- `과매도 20 과매수 150` → 그대로 수락. RSI는 0~100이므로 매도 신호가 영원히 발생하지 않음
- 같은 계열: `50 50`(경계 중첩), `과매도 80 과매수 20`(모순 → 조용히 재정렬), MA `20 20`(교차 불가), RSI 기간 `0`(합성 시 몰래 14로 치환)
- 수정안: 파라미터별 범위·불변식(oversold<overbought≤100, short<long, period≥2) 검증 + 위반 시 되묻기

### BF-10 [Medium/Slot Filling] 필터 단계는 어떤 입력이든 조용히 소비 — "근데 삼성전자만 하면 안돼?" → "필터 없음"으로 진행
- `_parse_filters`가 항상 `filters_asked=True` 반환 → 무관한 질문·요청이 통째로 사라짐
- 수정안: 필터 어휘(EMA/거래대금/RSI/없음 계열)가 전혀 없으면 완료 처리하지 않고 되묻기

### BF-11 [Medium/State Machine] 빌더 중 단일 종목 전환 요청 무시 — "그냥 삼성전자만 테스트할래"
- 빌더 모드는 분류기를 거치지 않아 종목 지정 테스트 요청(분류기라면 FR-STR-068 단일 종목 경로)이 조용히 무시되고 진행 중 질문만 반복
- 수정안: 빌더 스텝에서 종목명+단독 큐(`만|단일|테스트`) 감지 시 단일 종목 모드 전환 확인

### BF-12 [Medium/Slot Filling] ETF 유니버스에서 "저평가 가치주" 선택 시 사유 없이 같은 질문 반복
- 코드가 의도적으로 채우지 않지만(재무지표 불가) 사용자에게 이유를 말하지 않음 — 단일 종목 모드의 차단(설명 후 되묻기)과 비대칭
- 수정안: `_SINGLE_ASSET_BLOCKED_TYPES`처럼 ETF 차단 사유 문구 추가

### BF-13 [Medium/Parameter Parsing] "손절 10프로/10퍼센트" 결정적 미인식 — LLM 백스톱 의존
- `_PCT_NUM_RE`가 `%` 기호만 인식. 라이브에서는 LLM 백스톱이 구제(확인됨)하나, LLM 미가용 시 같은 질문 무한 반복. `프로|퍼센트|퍼`는 흔한 핵심 표기라 결정적 처리 대상(feedback_nl_parser_hybrid)
- 수정안: `_PCT_NUM_RE`에 `(?:%|프로|퍼센트|퍼)` 허용

### BF-14 [Medium/Slot Filling] 복합 답변의 후속 슬롯 유실 — "14일로 하고 과매도는 25 과매수는 80"
- rsi_period 단계에서 14만 채우고 25·80은 버림 → 방금 말한 값을 다시 물음
- 원인: 스텝 파서가 현재 슬롯만 해석(`_PARAM_STEP_PARSERS`)
- 수정안: 파라미터 스텝에서도 같은 전략의 다음 스텝 파서를 시도해 남은 값 흡수

### BF-15 [Medium/Slot Filling] 영어 답변 무한 재질문 루프 — "I don't know", "KOSDAQ please"(일부만 인식)
- 랜덤워크에서 english 페르소나 133/133 대화가 40턴 초과(무한 루프 상당). "몰라"는 기본값 처리되지만 영어 등가 표현은 미인식, 안내도 없음
- 수정안: N회 연속 미인식 시 "이해하지 못했어요 — 아래 선택지에서 골라 주세요" 에스컬레이션(언어 무관 안전망)

### BF-16 [Medium/Parameter Parsing] 미지원 지표 감지 공백 — 이치모쿠·VWAP·PEG·PCR·피보나치·엘리엇·캔들패턴
- `_mentioned_unsupported_concepts`가 전부 미감지 → 룰 파스 실패 후 LLM 폴백. 라이브 확인 결과 환각 매핑은 없었으나 "미지원 지표" 안내 없이 일반 되묻기만 나감 → 사용자가 같은 표현을 계속 재시도하는 막다른 길(STEP 7 요구 위반)
- 수정안: 미지원 개념 목록에 위 지표 추가(파서 커버리지 가드 원칙 — 구현 시 목록 제거)

### BF-17 [Low/Prompt] "0개"·"0개월" 입력 시 "최대 0종목으로 하겠습니다" 확인 후 재질문
- 0이 falsy라 미채움 처리되는 것은 우연히 올바르나, ack 문구가 0값을 복창해 어색. 99999개는 수락 후 엔진 보정(→100)이 **무통지** 클램프
- 수정안: count/기간 0 거부 문구, 클램프 시 notices 노출

### BF-18 [Low/State Machine] "처음부터 다시. 이번엔 코스닥으로" → 리셋 후 코스닥 유실
- restart 분기가 나머지 문장을 시드로 쓰지 않고 버림 → 방금 말한 조건을 또 물음
- 수정안: restart 시 잔여 텍스트로 `seed_state` 적용

### BF-19 [Info/Parameter Parsing] 룰 파서 표기 커버리지 편차(설계 내 동작 확인)
- `PER under 10`·`PER <= 10`·`PER가 십 이하`는 룰 파스 불가 → LLM 폴백(하이브리드 설계상 정상 경로, 조용한 누락 아님)
- `손절은 10 퍼센트`는 모멘텀 문장에서 룰 파스가 손절 없이 통과 — BF-13과 동일 근원의 메인 파서 버전. 단독 재현: `_parse_rule_based_strategy("코스피 모멘텀 상위 10종목, 손절은 10 퍼센트 익절은 20 퍼센트")` → sl/tp=null (**조용한 유실 — 수정 대상**)

## 최종 개선 제안 요약

1. **가장 치명적 설계 결함**: 빌더 모드가 분류기·정정·범위검증 없이 "첫 매치 1회 채움" 원칙으로만 동작 — 정정/취소/질문이 모두 '필드 답변'으로 강제 해석됨. 스텝 앞단에 경량 발화행위 판별(답변/정정/질문/이탈) 계층 권장
2. **State Machine**: 취소 확인 1회(BF-01), 정정 경로(BF-05), restart 시드 승계(BF-18), 빌더→단일종목 전환(BF-11)
3. **Slot Filling**: 정의 마커 시 파싱 차단(BF-03), 복합 답변 다중 슬롯 흡수(BF-14), 미인식 N회 에스컬레이션(BF-15), 필터 단계 무관 입력 비소비(BF-10)
4. **Validation**: 파라미터 범위·불변식 즉시 검증(BF-08/09) — 검증 agent 이전, 입력 시점에
5. **자연어**: `%` 한글 표기(BF-13/19), '말고' 정정(BF-06), 방향어(BF-07)
6. **커버리지**: 미지원 개념 목록에 이치모쿠·VWAP·PEG·PCR·피보나치·엘리엇·캔들패턴 추가(BF-16)
7. **추가할 테스트**: 이 하니스의 S2 랜덤워크·S3 지향 프로브를 `scripts/qa_builder_fuzz.py`로 승격해 회귀 게이트화
8. **향후 발생 가능성 높은 버그**: 새 전략 유형 추가 시 (a) 글로서리 미추가로 BF-03 재발, (b) `STRATEGY_PARAM_STEPS` 미등록 시 질문 없이 프리셋 확정, (c) 단일 종목 차단 목록 미갱신
