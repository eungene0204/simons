# 가상 사용자 QA

실제 사용자가 없으면 시험지(예시 81개·조각 조합 1000문항) 밖의 말투가 들어오지 않는다. 이 스킬은
**미스터리 쇼퍼**처럼 동작한다: 가상 사용자에게 원하는 전략(정답지)을 쥐여 주고 실제 대화 경로로 보낸 뒤,
받아 온 전략을 정답지와 대조한다. **① 실행 → ② 리포트 읽기 → ③ 결함 후보 검수 → ④ 보고·넘기기.**

## 먼저 지킬 것

- **대원칙 1**: 판정은 정답지(구조화 데이터)와 응답 구조 필드로만 한다. 하니스가 가상 사용자 발화를
  정규식으로 읽지 않는다. 새 판정이 필요하면 정답지 형식이나 응답 구조 필드를 늘린다.
- **대원칙 2**: 무엇을 고칠지는 사용자가 정한다. 이 스킬은 수리하지 않는다. 검수된 후보를 보고하고 고르게 한다.
- **비용**: 대화 하나 = Gemini 호출 2~9회(가상 사용자, `GOOGLE_API_KEY`) + 백엔드 해석 턴 최대 8회. 백엔드 턴은
  운영 LLM 레인(OpenRouter 무료 1000건/일)을 쓴다. 기본 10개를 넘겨 돌리면 실행 전에 사용자에게 알린다.
- **로컬 백엔드 필요**: `localhost:8000`(다른 포트는 `QA_BACKEND`). 공용 데모 계정·운영 서버로 돌리지 않는다.

## 1. 실행

```bash
uv run python scripts/qa_synthetic_users.py --n 10            # 페르소나 5종 × 2바퀴
uv run python scripts/qa_synthetic_users.py --n 5 --persona 툭툭 # 한 페르소나 집중
uv run python scripts/qa_synthetic_users.py --n 3 --seed 7      # 전략 성격 순서 재현
```

- 페르소나: 초보(풀어 말하기) · 구어체(오타·반말) · 툭툭(조금씩 말하기) · 경험자(약어로 한 번에) · 말바꾸기(값 정정).
- 가상 사용자 모델은 `SYNTH_USER_MODEL`(기본 `gemini-3.1-flash-lite`). 해석기(nemotron)와 다른 계열이어야 한다.
  `gemini-2.5-flash` 무료 등급은 하루 20건이라 대화 2~3개면 소진된다. 일일 한도에 걸리면 하니스가 남은 대화를 멈춘다.
  중간에 끊긴 대화는 대조하지 않는다.
  같은 계열이면 해석기가 알아듣기 쉬운 말만 나온다.
- 같은 시드여도 Gemini 출력은 매번 다르다. 시드는 페르소나·전략 성격 순서만 고정한다. 재현은 리포트의
  대화 문장을 `qa_multiturn_binding.py` 시나리오로 옮겨 한다.

종료 코드: 0 = 결함 후보 없음 · 1 = 결함 후보 있음 · 2 = 대조한 대화가 없음(한도 소진·생성 실패 — 점검 실패).

## 2. 리포트 읽기

결과는 `backend/logs/synthetic_users/<날짜>/<시각>.md`(사람용)와 `.jsonl`(기계용)에 있다(git 미추적).
대화마다 정답지·최종 전략 요약·⚠️ 항목·턴별 발화/질문/안내가 있다.

| ⚠️ 항목 | 출처 | 뜻 |
|---|---|---|
| `… 소실`·`… 값 오차`·`미탐지 …`·`값 소실 …` | `qa_template_detect.analyze`(예시 게이트 판정 정본) | 말한 조건·값이 최종 전략에 없거나 다름 |
| `명시 청산 규칙 소실` | 같음 | 정답지 `exit: true`인데 청산 신호 없음 |
| `답한 뒤에도 같은 질문 반복`·`이전 질문으로 되돌아감` | 응답 질문 문장 동일성 | 되묻기 답 미반영(**A**/**Q**) |
| `질문에 결속(pending_ask) 없음` | 응답 구조 | 다음 답이 새 발화로 분류될 위험 |
| `확정 필드 소실` | `explicit_fields` 비교 | 이전 턴에 정한 값이 사라짐 |
| `해석 실패` | `clarification_priority` | 빈 전략 |
| `8턴 안에 대화가 끝나지 않음` | 하니스 | 되묻기 고리 의심 또는 긴 대화 |

## 3. 결함 후보 검수 (필수)

⚠️는 **후보**다. 가상 사용자도 틀린다. 보고하기 전에 대화마다 턴 기록을 직접 읽고 셋 중 하나로 가른다.

- **결함**: 사용자가 분명히 말했는데 전략에 없거나 다르다. 또는 답했는데 같은 질문이 돌아온다.
- **생성 오류**: 가상 사용자가 정답지 값을 말하지 않았다. `확인 필요` 항목에 올라 있으면 먼저 의심한다.
  또는 정답지에 없는 조건을 지어냈거나 말바꾸기 정정이 끝나지 않았다. 결함으로 세지 않는다.
- **정상 동작**: 값 없는 조건을 되묻는 경우다(되묻기는 실패가 아니다, CLAUDE.md). 지역 격리·규제 거절도 정상이다.
  유니버스에 맞는 범위에서 질문하는 것도 정상이다.

결함으로 가른 건은 대표 턴의 백엔드 Trace를 `trace-triage`/`strategy-interpretation-fix`의
`trace_turn.py`로 찾아 원인 레이어를 짚는다. 시각과 발화로 찾는다. 합성 표시는 아직 Trace에 남지 않는다.

## 4. 보고·넘기기

CLAUDE.md 설명 스타일(결론 한 줄 → 번호 단계 → "한 줄로: …")로 보고한다.

- 표: 대화 id · 페르소나 · 판정(결함/생성 오류/정상) · 한 줄 요약.
- 결함은 묶어서(같은 원인으로 보이면 한 줄로) 제시하고, 어떤 것을 `strategy-interpretation-fix`로 넘길지 사용자가 고르게 한다.
- 생성 오류가 반복되는 형태가 보이면 `qa_synthetic_users.py`의 `SPEC_PROMPT`·`REPLY_PROMPT`를 고치자고 제안한다.
  결함 묶음이 두 번째 실행에도 남으면 trace-triage 4절처럼 회귀 테스트나 고정 시나리오로 승격하자고 제안한다.

## 주기 실행

지금은 수동 실행이다. 무인 주기 실행(launchd 등)은 사용자가 요청할 때만 건다. 이때 백엔드 기동 확인,
OpenRouter 한도 초기화(09:00 KST) 이후 시각, 결과 검수 방식(3단계는 사람·Claude 몫)을 함께 정한다.

## Gotchas

형식: `[날짜] 증상 → 원인 → 규칙` 한 줄. 이 스킬을 쓰다 실수하면 고친 뒤 맨 아래에 한 줄을 더한다.

- [11-13] 말한 ROE가 대조에서 빠짐 → 가상 사용자의 '전달함' 자기 보고를 믿고 미전달 항목을 대조에서 뺐다 → 항상 정답지 전체와 대조하고 미전달 항목은 '확인 필요'로만 표시한다(하니스 반영)
- [11-13] 10개 대화가 Gemini 429로 전부 건너뛰어졌는데 '결함 0'·종료 코드 0으로 끝남 → 일일 한도(2.5-flash 20건)를 몰랐고 전부 건너뜀을 성공으로 셌다 → 기본 모델을 flash-lite로 바꾸고, 한도 소진 시 멈춤·대조 0건은 종료 코드 2(하니스 반영)
