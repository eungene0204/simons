# 자유게시판 업데이트 소식

사용자에게 보이는 변화 하나(또는 한 배포에 묶인 여러 개) = 글 하나. 글은 **배포된 사실**만 알린다 —
게시판 독자는 글을 읽자마자 사이트에서 시험해 본다. 게시 도구는 `scripts/post_to_board.py`, 초안은
저장소 밖 `~/.config/nullstock-board/<날짜>-<slug>.json`(수정·삭제 비밀번호가 들어 있다).

## 1. 커밋 시점 — 대기 초안 등록

버그 수정이나 기능 추가를 커밋했으면 같은 작업에서 초안을 만든다.

1. **대상인지 가른다.** 대상 = 사용자가 화면·결과에서 차이를 느끼는 변화: 해석 실패·엉뚱한 되묻기
   수리, 결과 수치 정정, 새 조건·지표·화면 기능. 대상 아님 = 테스트·리팩터·문서·QA 하니스·관리자
   콘솔·배포 설정·X 게시물·연구노트 같은 콘텐츠. 애매하면 초안만 만들고 마무리 보고에 "게시 여부 확인
   필요"로 적는다.
2. `uv run python scripts/post_to_board.py new <slug>` → `kind`(bugfix/feature)·`commits`·`title`·`body`를 채운다.
   같은 배포에 묶일 대기 초안이 이미 있으면 새로 만들지 않고 그 초안 본문에 항목을 더한다.
3. 본문은 아래 **글 쓰기** 규칙대로 쓰고 `check`로 문구 검사를 통과시킨다(배포 근거 칸만 남는 상태).

완료 기준: `post_to_board.py list`에 이 변화의 초안이 `draft`로 있고, `check`의 남은 항목이 배포 근거 하나뿐이다.

## 2. 배포 확인 시점 — 게시

1. **배포를 확인한다.** 초안의 커밋이 main에 들어갔고 그 커밋 이후의 CI `deploy` 잡이 성공했는지
   `gh run list --workflow ci.yml --branch main`·`gh run view <id>`로 본다. 성공한 실행 URL과 커밋을
   초안 `deploy`에 적는다. 워크트리 브랜치·미병합·배포 실패·진행 중이면 여기서 멈추고 초안은 `draft`로 둔다.
2. **운영에서 한 번 본다.** 싸게 확인할 수 있으면(공개 API·화면) 고친 동작이 운영에 실제로 나오는지
   확인한다. 확인할 수 없으면 마무리 보고에 "운영 동작 미확인"이라고 적는다.
3. `uv run python scripts/post_to_board.py post <draft.json>` → 게시 URL이 초안에 기록된다.
4. 사용자에게 게시 URL과 제목·본문 전문을 답변에 붙인다.

완료 기준: 초안 `status`가 `posted`이고 `post_id`가 있으며, 답변에 URL과 전문이 있다.

## 글 쓰기

독자는 널스탁 내부를 모르는 게시판 이용자다. 사용자의 말로, 무엇이 달라졌고 어떻게 써 볼 수 있는지.

- **제목**: 달라진 점을 한 문장으로("매도 조건에 재무 지표(PER·ROE 등)를 쓸 수 있게 됐습니다").
- **본문 순서**: ① 전에 겪던 불편(사용자가 보던 안내 문구 그대로 인용 가능) → ② 이제 되는 것 →
  ③ 바로 따라 해 볼 수 있는 입력 예시 한 개 → ④ 알아 둘 동작(제약·기본 동작) → ⑤ "이상한 점은 게시판에 남겨 주세요".
- **용어**: 지표 이름(PER·RSI 등)과 화면에 보이는 문구는 그대로 쓴다. 파일명·함수명·필드명·엔진 버전·
  내부 단계명(인터프리터·컴파일러·레인)은 사용자 말로 바꾼다.
- **규제 안전**: 과거 데이터 시뮬레이션 도구로서의 사실만 쓴다. 예시 전략은 "이렇게 입력할 수 있다"로만
  제시하고 성과·우열·전망을 붙이지 않는다(CLAUDE.md 규제 안전 원칙).
- **보안 수정**: 무엇이 노출됐는지·어떻게 재현되는지 적지 않는다. "보안을 강화했습니다" 한 줄로 묶거나 게시하지 않는다.
- **분류·닉네임**: `공지`·`널스탁`(2026-10-18 개설 공지와 같다).

## Gotchas

- [11-13] 첫 게시 요청(재무 지표 청산) 때 기능은 워크트리 브랜치 커밋뿐이었음 → 커밋 = 반영으로 보면 독자가 시험해도 옛 안내가 나온다 → 게시는 CI deploy 성공 확인 뒤에만(`check`가 `deploy` 빈칸을 막는다)
