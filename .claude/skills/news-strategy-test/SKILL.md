# 뉴스 → 전략 백테스트

흐름: **① 기사 모으기 → ② 5개 이상 고르기 → ③ 전략 문장·spec 쓰기 → ④ 실행 → ⑤ 검수 → ⑥ 보고.**
산출물은 `~/nullstock-news/<YYYY-MM-DD>/<NN>-<slug>/`에 남는다. X에는 올리지 않는다(게시는 사용자가 요청할 때 `x-backtest-post`로).

## 먼저 지킬 것

- **규제 안전 원칙(CLAUDE.md)**: 이 작업은 "뉴스에 나온 업종·사건을 과거 데이터로 시험한 사례"다. 기사 선택 이유·`why`·해설은 사실만 쓴다 —
  "유망", "수혜", "지금 사야", "기대된다", "추천" 같은 평가·전망·권유 어휘를 쓰지 않는다. "기사에 나온 ○○ 업종을 대상으로 △△ 규칙을 과거 데이터에 적용"처럼 쓴다.
- **사전 고지(한 줄)**: 로컬 `.env`가 운영 DB라 해석·백테스트 이력이 데모 계정 이력으로 남고, 해석에 OpenRouter 무료 한도(1,000건/일)가 전략당 약 10건 쓰인다.
- **데모 계정은 한 번에 한 곳만 쓴다.** 같은 계정을 다른 세션(영상 녹화 등)이 동시에 쓰면 활성 대화가 서로 덮인다
  (2026-10-29: 남의 "현대자동차 관련주" 대화가 끼어들어 매수 신호 질문으로 멈춤). 실행 전 `ListAgents`로 다른 세션이 앱을 쓰는지 보고, 겹치면 사용자에게 묻는다.
  계정은 `GUEST_ID` 환경 변수로 바꿀 수 있지만(기본 `guest_5312`), 다른 게스트는 실제로 나눠 준 계정일 수 있어 사용자가 정한 경우에만 쓴다.

## 무인 실행 (매일 12:00)

`scripts/daily.sh`가 launchd(`~/Library/LaunchAgents/im.nullstock.news-strategy-test.plist`)로 매일 12:00 KST에 `claude -p "/news-strategy-test 무인 실행 …"`을 띄운다(로그 `~/Library/Logs/nullstock-news-daily.log`).
요청에 "무인 실행"이 있으면 물을 사람이 없으므로 아래처럼 바꿔 진행한다 — 나머지 절차는 같다.

- 사전 고지·질문(`AskUserQuestion`)을 하지 않는다. 사용자에게 물어야 할 일은 그 전략을 건너뛰고 `report.md`에 이유를 적는다.
- 다른 세션이 데모 계정·9222를 쓰고 있으면(`run_test.sh`가 "[중단] 9222" 출력) 10분 간격으로 최대 3번 다시 시도하고, 그래도 막히면 남은 전략을 건너뛴다. 남의 브라우저를 끄지 않는다.
- 끝나면 ⑥ 보고 내용을 `~/nullstock-news/<날짜>/report.md`로 쓴다: 사진은 `![](NN-slug/shot_b_overview.png)`처럼 상대 경로로, 해설은 `note.txt` 전문을 코드블록으로, 전략마다 `link.txt` 링크를 `[널스탁에서 같은 전략으로 열기](…)`로. 맨 위에 요약 표, 맨 아래에 건너뛴·뺀 전략과 이유. 알림·파일 열기는 `daily.sh`가 한다.
- **결과(`result.json`)는 있지만 보고서에서 뺀 전략은 그 폴더에 `exclude.txt`(이유 한 줄)를 쓴다** — 연구노트 변환이 이 파일로 건너뛴다. 빠뜨리면 뺀 결과가 노트로 공개된다.
- 코드·스킬·데이터를 고치지 않는다(해석 결함은 보고만). 커밋·게시하지 않는다 — 연구노트 게시는 이 세션이 끝난 뒤 `daily.sh`가 `publish_news_notes.sh`로 한다(아래 "연구노트 게시").

## ① 기사 모으기

```bash
python3 .claude/skills/news-strategy-test/scripts/fetch_yonhap.py ~/nullstock-news/$(TZ=Asia/Seoul date +%F)          # 최근 24시간
```

경제·마켓+·산업·국제 피드를 모아 `news.json`과 `번호 | 시각 | 분야 | 제목` 목록을 낸다. 고르는 일은 스크립트가 하지 않는다 — 제목·요약을 직접 읽는다.

## ② 고르기 — 5개 이상, 서로 다른 전략 유형으로

엔진 기능으로 바로 옮겨지는 기사를 고른다:

| 기사 유형 | 전략 재료 |
|---|---|
| 업종·테마가 주인공(반도체 급등, 조선 호황, 해킹 사고→보안) | 그 업종/테마 유니버스 + 매수·매도 신호 |
| 실적 발표(역대 최대 영업이익, 실적 서프라이즈) | 영업이익 성장률 조건, 실적 서프라이즈 랭킹 |
| 주주환원(배당 확대, 자사주 소각) | 배당수익률·연속 배당 연수 조건 |
| 지수 급등락·변동성 | 시장 국면 필터, 급등·급락 뒤 보유 규칙 |
| 금리·환율 등 거시 | 엔진이 금리를 직접 못 쓰므로 관련 업종(은행·수출주 등)으로 옮길 수 있을 때만 |

- 정치·사건사고·연예처럼 업종이나 지표로 옮길 수 없는 기사는 고르지 않는다.
- 같은 사건을 다룬 기사(1보·종합)는 하나로 친다. 5개 전략이 같은 모양(전부 "업종 + 골든크로스")이 되지 않게 유형을 섞는다.
- 24시간 안에서 5개가 안 되면 `--hours 48`로 넓히고 그렇게 했다고 보고한다.

## ③ 전략 문장과 spec

전략 문장은 **유니버스 + 매수 신호 + 매도 신호를 모두 담는다.** 문장이 신호를 비워 두면 널스탁이 매수·매도를 되묻고, 그 선택은 칩이 아니라 문장으로 정해야 한다.
업종·테마 이름은 정본 카탈로그(`data/kg-theme-catalog.json`, `data/kg-naver-theme-catalog.json`)에 있는 이름을 쓴다 — 어휘에 따라 유니버스가 달라진다.

`~/nullstock-news/<날짜>/<NN>-<slug>/spec.json`:

```json
{"prompt": "반도체 관련주 중 20일 이동평균선이 60일 이동평균선을 위로 돌파하면 매수하고, 아래로 돌파하면 매도하는 전략",
 "answers": ["최대 10종목", "리밸런싱 안 함", "손절 안 함", "익절 안 함", "최근 5년 데이터", "1,000만원"],
 "post_name": "반도체 관련주 이동평균 돌파",
 "news": {"title": "<기사 제목 그대로>", "link": "<news.json의 yna.co.kr 링크>", "published": "<news.json의 시각>"},
 "why": "기사에 나온 반도체 업종을 대상으로 이동평균 교차 규칙을 과거 데이터에 적용"}
```

`answers`는 위 기본값(문장에 없는 설정은 가장 중립적인 값)을 쓴다. 문장에 손절·기간 등을 넣었으면 그 칩은 빼도 된다.

## ④ 실행

프론트(3000)·백엔드(8000)가 떠 있어야 한다(스킬은 서버를 띄우지 않는다). 전략 하나에 약 2~3분이며 차례로 돈다(동시 실행 금지 — 같은 계정 충돌):

```bash
for d in ~/nullstock-news/<날짜>/*/; do bash .claude/skills/news-strategy-test/scripts/run_test.sh "$d" || echo "[실패] $d"; done   # Bash timeout 600000, 길면 run_in_background
```

`run_test.sh`는 녹화 없는 브라우저로 입력 → 칩 답변 → 확정 → 실행 → 결과를 돌고(`x-backtest-post`의 `studio_record.mjs`·`capture.mjs` 재사용), 폴더에 `result.json`·`shot_*.png`·`note.txt`(해설, `make_note.py`)·`link.txt`·`trades.txt`를 남긴다.

**해석 절(2026-11-02 고정)**: `note.txt`에는 항상 "해석 (과거 데이터 기준, 사실과 계산만)" 절이 들어간다 — `make_note.py`의 `interpretation()`이 로그·지표 숫자로 만든다(손익 구조=승·패 횟수와 평균 크기, 벤치마크 차이, 연 회전·평균 보유, 최대 낙폭, 종목별 상·하위와 쏠림, 표본 30건 미만 안내, 한계). 사실과 산술만 쓰고 평가·전망·권유·"기사 때문에 그런 결과" 같은 인과 단정은 쓰지 않는다. 해석이 없는 `note.txt`·보고는 완성이 아니다. 새 문항을 더할 때도 이 규칙을 지킨다. 무인 실행의 `report.md`도 `note.txt` 전문을 싣기 때문에 해석이 같이 들어간다.

**연구노트 게시(2026-11-07)**: 결과는 저장소 루트에서 `uv run --frozen python .claude/skills/news-strategy-test/scripts/build_news_notes.py`(Pillow가 필요해 `uv run`)로 연구노트 데이터(`lib/notes/newsNotes.data.json`)와 사진(`public/notes/news/<slug>/`)으로 옮긴다 — 결과 폴더 전체를 다시 훑어 만들고, 해석이 문장과 다른 폴더는 스크립트의 `EXCLUDED`에 이유와 함께 넣는다. 그 뒤 `npx vitest run lib/notes components/notes`(편 수 `toHaveLength`도 올린다) → 배포(사진·열기 링크는 코드와 함께 나간다) → `npx ts-node --project tsconfig.scripts.json scripts/seed-research-notes.ts --slug-prefix=news-`(dry-run 신규 수 확인) → `--apply`. 노트에는 종목별 손익과 종목이 보이는 사진을 싣지 않는다. **자동 게시(2026-11-08 사용자 지시 — 뉴스 전략을 만들면 노트까지 자동으로)**: 무인 실행은 `report.md`가 생기면 `daily.sh`가 `scripts/publish_news_notes.sh`를 부른다 — origin/main 임시 워크트리(`~/nullstock-news/.publish-wt`)에서 위 변환 → 편 수 테스트 갱신·vitest → 시드 dry-run(신규 = 새 편 수) → 노트 세 경로만 커밋·main 푸시 → CI·배포 성공을 기다린 뒤에만 `--apply` → 운영 글·사진 주소 200 확인. 결과는 `report.md` 끝 "연구노트 게시" 절에 붙는다. 이미 올라간 편의 내용이 바뀌면(스크립트 수정 등) 멈춘다 — 사람이 확인하고 `--allow-changed`로 다시 돌리며, DB 본문은 `--overwrite`를 따로 해야 바뀐다. 손으로 돌린 실행도 같은 명령으로 올린다. 엔진 버전은 `ENGINE_BY_DATE`, 없으면 날짜 폴더의 `engine.txt`(`daily.sh`가 실행 시각에 남긴다)를 쓴다.

**연구노트 글 구성(2026-11-08, AEO·GEO)**: 틀은 `lib/notes/newsNotes.ts`가 조립한다 — 제목은 질문형 과거형 문형 7개(`TITLE_PATTERNS`: 수익 여부·수익률·낙폭·과거 데이터 결과·승률·벤치마크 차이·매매 횟수)를 글 순서대로 돌려 쓰고, 순서는 결과 표 → 규칙·설정값 → 해석 → 기사 → 계산 기준. 문장과 FAQ는 잘려 인용돼도 뜻이 통하게 규칙 이름·구간·수치를 자체로 갖는다. 그래서 `post_name`은 사람이 검색할 말로 쓴다(지표·값·업종이 드러나게, 예: "코스피200 RSI 25 아래 매수 후 20일 보유"). 숫자 없는 공통 문구를 늘리지 않는다.

**같은 전략으로 열기 링크(2026-10-30 도입)**: `make_note.py`가 입력 문장을 널스탁 입력창에 채워 여는 링크를 `link.txt`와 `note.txt`의 "널스탁에서 같은 전략으로 열기:" 줄에 남긴다 — `https://www.nullstock.im/?prompt=<문장>&utm_source=news&utm_medium=referral&utm_campaign=<날짜>-<NN-slug>`(캠페인은 폴더 이름에서 자동)(한글은 인코딩하지 않고 공백은 `+`, 주소를 깨는 글자만 `%XX` — 짧게 유지. 줄은 `note.txt`의 "널스탁 해석" 절 바로 뒤에 둔다). 규칙은 `x-backtest-post`의 "이 전략 그대로 열기"와 같다: 경로는 홈(`/`)이어야 하고(다른 경로는 비로그인 방문자를 홈으로 돌려보내며 쿼리를 잃는다), 앱은 문장을 채우기만 하고 보내기는 방문자가 누르며, 문장은 1,000자 이하다. 결과를 다시 만들지 않고 링크만 다시 뽑을 때는 `python3 scripts/make_note.py <폴더>`. X에 올릴 때는 `x-backtest-post`가 `utm_source=x` 링크를 따로 만든다.

**"준비된 답이 없는 질문"으로 멈추면**: 매수·매도 신호를 묻는 질문이면 문장에 신호를 넣어 고친다. 그 밖의 설정 질문이면 가장 중립적인 칩 글자를 `answers`에 더한다. 고친 뒤 그 폴더만 다시 돌린다.

## ⑤ 검수 — 전략마다

- `result.json`의 `summary`(널스탁 해석)가 문장과 같은가: 유니버스가 기사 업종과 일치하는지, 문장에 없는 조건이 끼지 않았는지. 어긋나면 그 전략은 결과에서 빼고 증상을 보고한다(`strategy-interpretation-fix` 제안). 고쳐서 맞추려 들지 않는다.
- 화면에 다른 대화(문장에 없는 종목·테마)가 보였으면 계정 충돌이다 — 그 결과는 버리고 위 "데모 계정" 항목대로 처리한다.
- 사진을 열어 본다. **전략마다 3~4장을 고른다**: `shot_b_overview`(지표+수익 곡선)는 항상, 나머지는 이 결과의 특징을 보여 주는 것(`c_contrib` 종목·섹터 기여도, `d_dist` 수익률·보유 기간 분포, `e_factor` 팩터, `f_risk` 회전율·하방 위험, `i_ai` AI 점수 카드). `g_stocks`·`h_trades`는 일부 행(코드순·가장 이른 거래)이라 쓸 때 그렇다고 밝힌다.
- `note.txt`에 "해석" 절이 있는지 확인한다(없으면 `python3 scripts/make_note.py <폴더>`로 다시 만든다). 해석의 숫자가 `result.json`·`trades.txt`와 맞는지 한두 개 대조한다.
- `note.txt`의 "널스탁 해석" 줄은 `- <칸 이름>: <값>`이다(예: `- 업종: 이차전지`). `make_note.py`의 `card_pairs`가 앱 카드 칩 라벨 목록(`CARD_LABELS`, 앱 `builderProgressPresentation.ts`와 같은 이름)으로 칸을 나누고 "종목 N개 펼쳐보기" 같은 버튼 글자는 버린다 — 줄 순서로만 짝지으면 버튼 글자 때문에 칸이 한 칸씩 밀리고 마지막 "리스크 관리" 값이 빠진다(2026-11-04 수리, 이전 노트 25건이 이 상태). 앱이 새 칩 라벨을 더해 `make_note.py`가 "[중단] 해석 카드 칩의 값 줄이 하나가 아니다"로 멈추면 그 라벨을 `CARD_LABELS`에 더하고 다시 만든다.
- 수익 곡선에 급락·급등이 있으면 `trades.txt`에서 그 무렵 큰 거래를 찾아 확인된 사실만 해설에 한 줄 덧붙인다.

## ⑥ 보고

기사 제목은 항상 `spec.json`의 `news.link`로 링크를 건다(`[제목](https://www.yna.co.kr/view/…)` — 표 안에서도).
전략마다: 링크 걸린 기사 제목 → `[널스탁에서 같은 전략으로 열기](<link.txt>)` → 고른 사진(Read로 띄운다) → `note.txt` 전문(코드블록). 끝에 표 하나(기사 | 전략 | 수익률 | 벤치마크 | MDD | 열기 — 마지막 칸은 `[열기](<link.txt>)`)와,
빼거나 실패한 전략과 그 이유, 내가 정한 값(문장 구성·기본 칩)을 적는다. `open ~/nullstock-news/<날짜>`로 폴더를 연다. 게시하지 않았다고 밝힌다.
