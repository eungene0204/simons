# 백테스트 결과를 X에 올리기

흐름: **① 전략 문장 정하기 → ② 로컬 앱에서 백테스트 → ③ 사진 3장 캡처 → ④ 글 작성 → ⑤ 미리보기 → ⑥ 게시.**
영상으로 올릴 때는 ②③을 [영상 모드](#영상-모드)로 바꾼다(첫 글에 사진 대신 동영상 1개).
게시는 공개·되돌리기 어려운 외부 전송이다. ⑤ 미리보기 없이 게시하지 않고, 사용자가 올리라고 한 글만 올린다.

## 먼저 지킬 것

- **규제 안전 원칙(CLAUDE.md)**: 글은 "백테스트 사례"다. "추천 전략", "유망", "지금 사야 할", 시장 전망,
  종목·전략 추천 표현을 쓰지 않는다. 결과는 과거 데이터 기준 수치로만 서술하고 평가·권유 어휘를 넣지 않는다.
- **대원칙 2**: 사용자가 정하지 않은 결정(어느 예시, 기존 글 삭제)을 대신 내리지 않는다.
  고르라고 한 경우에만 고르고, 무엇을 골랐는지 보고한다.
- **면책 문구는 넣지 않는다**(2026-10-05 사용자 상시 지시). "과거 데이터 기반 시뮬레이션 결과이며 미래 수익을
  보장하지 않습니다" 줄을 글에 넣지 않는다. 사용자가 다시 넣으라고 할 때만 넣는다.
- **인용(quote)·답글은 내가 쓴 글이나 나를 멘션한 글에만 API로 가능하다.** 다른 계정(정치인·뉴스 포함) 글은
  X가 403으로 거부한다(2026-10-04 실측). 그 글을 인용하려면 사용자가 X 앱에서 직접 해야 한다 — 사진·글
  문안만 준비해 준다. 기사 주소를 글 본문에 넣는 것은 가능하다(링크 포함 글은 건당 비용이 더 높다).
- **개선 우선순위·행동 제안은 올리지 않는다.** AI 리포트의 "개선 우선순위"는 사용자 행동 제안이라 규제 원칙과
  충돌한다. AI 리포트는 "핵심 요약"만 복사하고(2026-10-04 사용자 선택), 나머지는 먼저 묻는다.
- **기존 글을 수정·삭제하는 것은 사용자 몫이다.** X API로는 글 수정이 안 되고, 삭제도 요청 없이 하지 않는다.
  잘못 올린 글이 생기면 상태를 조회해 보고하고 처리 방법을 묻는다.

## ① 전략 문장

- "우리 예시"를 쓰라고 하면 `components/strategy/StrategyExampleTabs.tsx`의 `prompt`를 **글자 그대로** 입력한다.
  어느 예시인지 지정이 없으면 하나를 골라 이유와 함께 알리고, 첫 화면의 "예시로 시작해 보세요!" 카드가 무난하다.
- 테마어는 정본 카탈로그에 있는 이름으로 쓴다. 같은 뜻이라도 어휘에 따라 유니버스가 달라진다
  (2026-10-04 사고: "치킨"은 식품 업종 전체로 해석, 테마 "닭고기"·"육계"는 7~9종목). 입력 후 요약의
  **유니버스가 말한 대상과 일치하는지** 확인한다(`data/kg-theme-catalog.json`, `data/kg-naver-theme-catalog.json`).

## ② 백테스트 (로컬 앱, Playwright)

사전: 프론트(3000)·백엔드가 떠 있어야 한다. 임시 폴더에 Playwright를 설치한다(저장소 의존성 불변):

```bash
PW=<scratchpad>/pw; mkdir -p $PW && cd $PW && npm init -y >/dev/null && npm i playwright && npx playwright install chromium
cp /Users/eugene/nullalgo/simons/.claude/skills/x-backtest-post/scripts/*.mjs $PW/   # ESM은 node_modules 옆에서만 import가 된다
export GUEST_PW="$(python3 -c "import json;print([x for x in json.load(open('guest-accounts.local.json')) if x['guestId']=='guest_5312'][0]['password'])")"  # 저장소 루트에서. 값을 출력·기록하지 않는다
(nohup node browser_server.mjs > server.log 2>&1 &); sleep 15; cat server.log   # "ready"
```

- 로그인은 무기한 데모 게스트 `guest_5312`(id 50)를 쓴다. **로컬 `.env`가 운영 DB라 백테스트 기록이 운영 DB에
  이 계정 이력으로 남는다** — 사용자에게 알린다. 해석에는 OpenRouter 무료 한도가 쓰인다.
- 대화는 `node step.mjs type "<문장>"` → `wait 40` → `text`로 진행한다. 되묻기 카드는 칩을 `click`한다
  (예: "비중 조정", "손절 -15%", "최근 3년 데이터", "1,000만원", "이 전략으로 확정", "백테스트 시작하기").
  "직접 입력"을 누르기 전에는 입력창이 없는 카드가 있다.
- **새 대화는 깨끗해야 한다.** 이전 대화의 설정(리밸런싱·익절 등)이 이어진다 — `click "대화 종료"` 후
  `goto http://localhost:3000/analytics/new`. 이전 결과가 복원돼 입력창이 없으면 `click "결과 닫기"`.
- 예시에 없는 항목(리밸런싱·익절 등)은 가장 중립적인 값("안 함")으로 답하고 글에 밝힌다. 사용자가 값을 주면 그것을 쓴다.
- **해석 요약이 문장과 어긋나면 올리지 않는다**(예시에 없는 조건이 끼거나 "해석하지 못했어요"가 나옴).
  2026-10-04 "반도체 ETF 60일선 위 보유"가 "ETF만 대상으로"를 거래대금 조건으로 오해했다. 고치려 들지 말고
  증상과 트레이스(`backend/logs/agent_traces/<날짜>.jsonl`의 LLM span 모델명)를 사용자에게 보고하고
  `strategy-interpretation-fix` 스킬을 제안한다. 다른 예시로 바꾸려면 알린다.
- 이동평균 기간 등 문장에 없는 값을 널스탁이 정한 경우(예: "단기/장기" → 5일-20일·20일-60일) 글에 그 사실을 적는다.
- 결과가 나오면(`백테스트 완료 — … 수익률 …%`) 손실이어도 있는 그대로 올린다.

## ③ 사진 — 한 가지에 치우치지 않고 여러 종류를 쓴다 (2026-10-05 사용자 지시)

```bash
node capture.mjs <접두사>     # 결과 화면에서 → <접두사>_<코드>_<이름>.png 최대 9장(없는 섹션은 건너뛴다)
```

| 코드 | 내용 | 쓰임 |
|---|---|---|
| b_overview | 핵심 지표 + 수익 곡선 | **첫 글에 항상** |
| c_contrib | 종목별·섹터별 기여도 | 첫 글 기본 |
| d_dist | 거래 수익률·보유 기간 분포(막대) | 선택 |
| e_factor | 팩터 회귀(시장·규모·가치·모멘텀 베타) | 선택 |
| f_risk | 매매 회전율·VaR/CVaR·63일 롤링 샤프/베타 | 선택 |
| g_stocks | 종목 분석 탭 상단 10행 | 선택 — **종목 코드순 첫 10개라 대표성이 없다** |
| h_trades | 매매 기록 탭 상단 9행(매수·매도 사유) | 선택 — **가장 이른 거래 9건**이다 |
| i_ai | AI 리포트 점수 카드(점수·LEVEL·성장성/안정성/일관성) | **AI 핵심 요약 답글에 첨부** |
| a_strategy | '내 전략' 팝업 | 입력 문구·조건은 텍스트로 쓰므로 보통 안 붙인다 |

- **첫 글은 b + c에 더해 이번 결과에서 보여 줄 만한 사진을 1~2장 더 골라 3~4장을 붙인다**(글당 최대 4장).
  매번 같은 조합(b+c)을 반복하지 않는다 — d·e·f·g·h 중 이번 전략의 특징(거래가 잦다 / 손절 구간에 몰렸다 /
  특정 팩터 쏠림 / 보유 기간이 짧다 등)을 가장 잘 보여 주는 것을 고르고, **직전 글에서 쓴 조합과 다르게** 짠다.
  어떤 사진을 골랐고 이유가 무엇인지 미리보기 보고에 적는다.
- 붙인 사진이 다루는 수치는 해석 글에 **사진 속 값 그대로** 한두 줄 덧붙인다(평가 어휘 없이. 예: "거래 수익률 분포에서
  -15~-5% 구간이 212회입니다"). g·h 사진은 일부 행이라는 점을 글에 밝힌다("종목 코드순 상위 10개", "가장 이른 9건").
- AI 핵심 요약 답글(⑥)에는 `i_ai` 한 장을 붙인다(속설 시리즈는 답글에 `b_overview`+매번 다른 결과 항목 사진을 붙인다 — 속설 글 형식 4).
2배 해상도(CDP `clip.scale`)라 파일당 50~280KB(한도 5MB). **캡처를 전부 열어 눈으로 확인**한다(툴팁·잘림·팝업 잔존·
상단 고정 바 겹침). 개요에서 스크롤해 찍는 사진은 스크립트가 고정 헤더를 숨기고 찍지만, UI가 바뀌면 다시 겹칠 수 있다.
백테스트 기록 페이지에서 지난 결과를 다시 열 때는 `click "백테스트 기록"` → 카드 클릭 → 캡처(어느 탭에서든 된다).

## 영상 모드(구식) — 화면 전체 녹화 (2026-10-10 도입, 스튜디오 모드로 대체됨 — 줌 연출이 필요 없을 때만)

사진 대신 "문장 입력 → 해석 카드 → 되묻기 칩 → 결과" 흐름을 30~40초 영상으로 보여 준다. 첫 영상
게시: 글 2108860730703589385("이평선 골든크로스 따라가기", 37초, 1MB).

사전: ②의 Playwright 임시 폴더 + `brew install ffmpeg`(Playwright 내장 ffmpeg는 녹화 전용이라 mp4 변환이 안 된다).
**설치된 ffmpeg에는 `drawtext`가 없다** — 영상 위 글자(자막)는 지금 못 넣는다.

```bash
(nohup node record_server.mjs > server.log 2>&1 &); sleep 20; cat server.log   # "ready" — 로그인은 녹화 밖, 새 화면부터 녹화
node rstep.mjs wait 2; node rstep.mjs type "<문장>"     # 한 글자씩 입력(35ms) — 이후 ②와 같이 wait/text/click
node rstep.mjs hold 5                                  # 결과가 뜨면 마우스를 치우고 정지(차트 툴팁이 남지 않게)
pkill -TERM -f "node record_server.mjs"; sleep 5; cat server.log   # "video videos/<id>.webm"
ffmpeg -v error -y -i videos/*.webm -c:v libx264 -pix_fmt yuv420p -crf 20 raw.mp4
```

- `rstep.mjs`는 `step.mjs`와 같되 `type`이 사람처럼 치고, 동작마다 시각을 `marks.log`에 남긴다.
  **영상 시각 ≈ marks 시각 − 첫 줄 시각 + 약 4초**(컨텍스트 생성~ready 사이). 편집점은 이 추정으로 잡고,
  `ffmpeg -ss <초> -t <길이> -i raw.mp4 -vf "fps=1/2,scale=240:-1,tile=6x3" -frames:v 1 t.png`로 접촉 시트를 떠서
  눈으로 확정한다(해석 카드 등장·결과 등장 순간).
- 편집은 `cut_video.sh raw.mp4 out.mp4 segs.txt` — `segs.txt` 한 줄 = `시작 끝 배속`(영상 초). 끝에 마지막 장면을
  2.5초 정지로 붙이고 30fps·H.264·faststart로 낸다. 10-10 실측 구성(37초):
  입력 1.5배 → 해석 대기 약 60초를 15배 → 해석 카드 4초 1배 → 칩 클릭 각 3.6초 1.5배(대기 구간 삭제) →
  백테스트 실행 15초를 6배 → 결과 2.4초 + 정지.
- **빨리 감았다는 안내 문구는 글에 넣지 않는다**(2026-10-13 사용자 상시 지시 — "영상은 입력부터 결과까지 실제 화면이고, 대기 시간만 줄였습니다" 같은 표현 전부). 영상 속 배속 배지는 그대로 둔다.
- 녹화 화면 왼쪽 "대화 기록"에 데모 계정의 지난 전략 문장들이 보인다. 첫 입력 직후 `node closelog.mjs`로 패널을 접는다
  (접는 순간은 편집에서 잘라낸다). `closelog.mjs`는 `[aria-label="대화 기록 닫기"]`를 누르는 한 줄짜리다.
- **녹화를 끄기 전에 같은 브라우저에서 사진·AI 리포트를 얻는 편이 낫다**: 결과가 뜨고 `hold`까지 찍은 뒤 `capture.mjs`·
  `click "리포트 생성"`·`ai_shot.mjs`를 돌리고 나서 녹화를 끈다 — 그 구간은 편집에서 버린다(캡처 스크립트는
  녹화 브라우저의 화면도 찾는다). 아래 재실행은 이 방법을 놓쳤을 때의 대안이다.
- 녹화 종료(`pkill -TERM`)는 `handleSIGTERM:false`로 영상이 끝까지 닫힌다(10-10 재녹화로 확인).
- **녹화 브라우저는 결과를 저장하지 않고 닫히므로 '백테스트 기록'에 남지 않는다**(10-10 실측). 해석 글의 조건·비용·기준값,
  AI 핵심 요약, `i_ai` 사진은 녹화를 끈 뒤 `browser_server.mjs`로 **같은 문장·같은 칩 답변을 다시 돌려** 얻는다
  (결정론이라 수치가 같아야 한다 — 다르면 게시하지 말고 보고). 결과 화면에서 `node capture.mjs <접두사>`로 '내 전략'
  팝업(`a_strategy`, 체결·비용 확인용)을 찍고, AI 리포트가 "아직 생성되지 않았습니다"면 `click "리포트 생성"` 후
  기다렸다가 `node ai_shot.mjs <파일>.png`로 점수 카드만 찍는다(capture.mjs는 리포트가 없으면 `i_ai`를 건너뛴다).
- 게시: `post_to_x.py --file post1.txt --long --video out.mp4 --post`(MP4 1개, 512MB 이하, 사진과 같이 못 붙인다 —
  스크립트가 조각 업로드 후 X의 인코딩 완료까지 기다린다). AI 핵심 요약 답글은 사진 모드와 같다(`i_ai` 첨부).

## "이 전략 그대로 열기" 링크 (2026-10-10 도입)

글 끝에 방문자가 같은 문장으로 바로 시작할 수 있는 링크를 붙인다. 링크는 `https://www.nullstock.im/?prompt=<문장>&utm_source=x&utm_medium=social&utm_campaign=<이름>`이고,
앱(`lib/strategy/strategyOpenLink.ts`)이 문장을 **입력창에 채우기만** 한다. 보내기는 방문자가 누르고,
로그인 전이면 기존 로그인 게이트가 문장을 보관했다가 로그인 뒤 이어서 처리한다.

```bash
printf '%s' "<입력한 문장 그대로>" > prompt.txt
uv run python scripts/post_to_x.py --file post1.txt --long --video out.mp4 --open-link prompt.txt --campaign myth-01   # 미리보기
```

- **경로는 홈(`/`)이어야 한다.** `/analytics/new` 등 다른 경로는 비로그인 방문자를 홈으로 돌려보내면서 쿼리를 잃는다(10-10 실측).
- 문장은 1,000자 이하(앱 한도와 스크립트 한도가 같다). `--campaign`은 글마다 다르게 붙여 유입을 구분한다
  (속설 시리즈 `myth-<번호>`, 일반 게시 `post-<YYYYMMDD>`).
- X는 링크를 길이와 무관하게 23자로 센다 — 스크립트의 가중 글자 수도 그렇게 센다.
- **앱 기능이 프로덕션에 배포된 뒤에만 링크가 동작한다.** 게시 전 운영 주소로 열어 입력창이 채워지는지 확인한다.

## 속설 검증 시리즈 (2026-10-10 도입)

"RSI 30 아래면 반등한다", "PER 낮은 주식은 결국 오른다" 같은 흔한 매매 속설을 널스탁에 그대로 넣고 과거 데이터로
돌린 결과를 영상 모드로 보여 준다. 영상 모드 + 링크 절차를 그대로 쓰고, 다음을 더 지킨다.

- **문장은 파싱 검증을 거친 예시에서 고른다**(`StrategyExampleTabs.tsx`). 새 문장을 쓰면 게시 전에 예시 게이트와 같은 무게로 확인한다.
- **해석 카드가 속설과 같은 말인지 먼저 본다.** 10-10 "RSI가 70 이상으로 올라오면 매도"가 "RSI 70 하향 반전"으로
  해석됐다(올라오면 파는 것과 내려올 때 파는 것은 다르다). 어긋나면 그 주제는 접고 증상을 보고한다.
- **결과가 상식 밖이면 게시 전에 데이터·엔진부터 의심한다.** 10-10 "PER 8 이하" 5년 백테스트가 -91.93%(MDD -92.17%,
  승률 15.2%)로 나왔는데, 원인은 엔진이 PER이 전부 빈 적자 기업 318종목에 `주가÷음수 EPS`로 음수 PER을 넣어
  "8 이하"를 통과시킨 결함이었다(`engine/data_resolver.py::_resolve_computable_ratios`). 확인 방법: 결과 로그의 TOP/BOT
  종목을 `data/ohlcv/<코드>.parquet`에서 조건 칸 값으로 대조한다. 속설 검증은 "검증"이라는 이름 때문에 틀린 결과가
  더 큰 오해를 만든다.
- **"속설이 맞다/틀렸다"는 판정을 쓰지 않는다.** 결과 수치와 정의만 쓴다(규제 원칙 — 전략 우열 판단·전망 금지).
  글의 **첫 줄은 `[속설 검증 #<번호>] "<속설 한 줄>"`이다**(2026-10-13 사용자 상시 지시 — 전략 설명 문장 뒤에 두지 않고, 이것이 글의 첫 문장이어야 한다). 전략 이름·소개 문장은 그 다음 줄부터 쓴다. 아래 ④의 "`<전략 이름> 전략을 백테스트 해봤습니다.`로 시작" 규칙은 속설 시리즈에는 적용하지 않는다.
- 문장에 없는 값(기간·리밸런싱·익절)은 시리즈 안에서 같게 둔다: **최근 5년, 리밸런싱 안 함, 익절 안 함, 1,000만원**
  (문장이 정하면 문장을 따른다). 글에 밝힌다.
- 다룬 주제와 결과는 `references/myth_series.md`에 한 줄씩 남긴다(번호 중복·주제 반복 방지).

**글 형식 — 2026-10-13 사용자 지시로 바뀐 것(#4부터 적용, 아래가 위의 옛 규칙·템플릿보다 우선한다)**

1. **첫 줄은 `[속설 검증 #<번호>] "<속설 한 줄>"`.** 전략 이름·소개는 그 아래에 쓴다.
2. **이전 글과 같은 틀 문장을 반복하지 않는다.** 문안을 쓰기 전에 직전 속설 글 3~4개를 X API로 읽어
   (`GET /2/tweets?ids=…&tweet.fields=note_tweet`, Bearer 토큰은 출력하지 않는다) 소제목·설명 문장·지표 풀이 문구가
   겹치지 않게 새로 쓴다. 숫자와 사실은 그대로, 표현만 바꾼다. `post_to_x.py --open-link`는 고정 라벨
   ("이 전략 그대로 열기")을 붙이므로 쓰지 않고, `post_to_x.strategy_open_url(prompt, "myth-<번호>")`로 만든 주소를
   내 문구("같은 문장으로 직접 돌려 보기: <주소>") 안에 직접 넣는다.
3. **"영상은 …실제 화면이고 대기 시간만 줄였습니다" 류 안내 문구를 쓰지 않는다**(영상 속 배속 배지는 그대로).
4. **답글 사진 — 결과 페이지는 항상, 나머지는 매번 다른 항목으로(2026-10-14 사용자 상시 지시, #11부터 적용).**
   답글에 사진 2~4장: **`b_overview`(핵심 지표 + 수익 곡선 = 결과 페이지)는 매번 반드시 넣고**, 나머지 1~3장은
   `c_contrib`(기여도)·`d_dist`(거래 수익률·보유 기간 분포)·`e_factor`(팩터 회귀)·`f_risk`(회전율·VaR/CVaR·롤링 샤프)·
   `g_stocks`(종목 분석)·`h_trades`(매매 기록)에서 **이번 전략의 특징을 가장 잘 보여 주는 것**을 고른다(손절이 많으면
   d_dist, 소수 종목이 손익을 좌우하면 c_contrib, 잦은 매매면 f_risk, 특정 팩터 쏠림이면 e_factor 등).
   **직전 글(들)과 같은 조합을 반복하지 않는다** — 목적은 "널스탁이 이렇게 다양한 수치를 보여 준다"를 매번 다른 화면으로
   알리는 것이다. 고른 사진마다 사진 속 값을 글에 그대로 풀어 쓰고(종목은 기여도 절댓값 상위 10개 — 플러스·마이너스
   개수와 범위, 섹터는 보이는 행의 부호와 큰 값 / g·h는 일부 행임을 밝힌다), 마지막에 "이 화면은 …를 보여 주는 널스탁
   결과 탭 중 하나입니다"처럼 어떤 종류의 수치인지 한 줄로 알린다(평가 어휘 없이). **AI 리포트 점수 카드(`i_ai`)도 가끔 후보에 넣어도 된다**(2026-10-14 사용자 허용 — 매번 아님, 다른 항목과 돌려 가며). 점수 카드 사진만 허용이고 **AI 요약 본문은 여전히 올리지 않는다**. AI 리포트 생성은 한도로 3분 안에 안 끝날 수 있어, 점수 카드가 없으면(`i_ai` 미생성) 다른 항목으로 대체한다. 점수는 사진 속 값 그대로 풀고 "AI가 매긴 점수"라는 출처를 밝히되 평가·권유 어휘는 붙이지 않는다.
   사용한 조합은 `references/myth_series.md`의 해당 줄에 사진 코드로 남긴다(예: `사진=b+d+f`).
   (#4~#10은 `c_contrib` 한 장이었다 — 이 지시 이전 방식.)
4-1. **멘트도 매번 다르게(상시).** 첫 줄 태그 `[속설 검증 #N] "…"`을 뺀 모든 문장 — 도입 문장, 소제목, 지표 풀이,
   직접 확인한 것, 링크 안내 — 을 **직전 글 3~4개의 문안(`~/nullstock-cf/myth-*/post1.txt`·`post2_reply.txt`)을 읽고**
   겹치지 않게 새로 쓴다. 같은 소제목(예: "계좌가 어떻게 됐나")·같은 어미·같은 순서 틀을 되풀이하지 않는다(블록 순서도 바꿔 본다).
   숫자·사실·규제 원칙은 그대로, 표현과 구성만 바꾼다.
5. **AI 리포트 "핵심 요약" 본문은 올리지 않는다**(#4에서 사용자가 선택 — 요약 원문에 "실전 적용이 적절하지 않다고
   판단" 같은 투자 판단·전략 우열 서술이 있어 규제 원칙과 충돌). 요약에 그런 문장이 없고 사용자가 올리라고 할 때만 원문 그대로 쓴다.
6. **게시 전 직접 확인한 사실을 글에 넣는다** — 매수 표본 20~30건을 가격 데이터로 다시 계산해 신호 조건과 맞는지,
   큰 손실 거래의 원인(거래정지·갭하락 등). 확인하지 않은 원인은 쓰지 않는다.
7. **입력 문장을 소개하는 줄은 `널스탁에 이렇게 입력 했습니다`**(2026-10-13 사용자 지시, "입력 문장 그대로" 등 다른 표현 쓰지 않음). 그 아래에 문장을 큰따옴표(“…”)로 그대로 적는다.

**소리(2026-10-13 사용자 결정)**: 속설 영상은 **목소리 없이 BGM + 자막**이 기본이다(밝은 곡 `scripts/cf/bgm_bright.py` 기본·차분한 `bgm_calm.py` 대안, 자막이 설명을 대신하므로 단계마다 읽을 시간·값 자막). 목소리 입히기는 사용자가 다시 요청할 때만 — 둘 다 [references/voice_recipe.md](references/voice_recipe.md). 게시 전에 사용자가 들어 봐야 한다(소리는 직접 못 듣는다).

**녹화 함정(2026-10-13 실측)**
- **작업 폴더는 녹화마다 새로 만든다.** 같은 폴더에서 다시 녹화하면 `marks.jsonl`에 이전 녹화 기록이 남아 편집 계획이
  이전 시각을 새 녹화의 첫 프레임에 눌러 붙인다 — 영상 전체가 홈 화면이 된다. 검수 시트에서 홈 화면(“퀸트 전략을
  백테스트하고…”)이 중간 장면에 반복되면 이 문제다(빌드 전 `marks.jsonl` 첫 기록의 오프셋이 음수가 아닌지, `type`
  `approach`가 1개뿐인지 확인).
- 칩을 누르면 다음 카드가 같은 자리에 곧바로 떠서 클릭 물결이 엉뚱한 칩 위에 남는다 → `studio_server.mjs`가 화면이
  바뀌면 물결을 지운다(반영됨).
- 칩 답변 직후 다음 질문이 그려지기 전에 스크립트가 먼저 확인해 "준비된 답이 없는 질문"으로 멈출 수 있다 → `studio_record.mjs`가 칩을 못 찾으면 1.5초 기다려 최대 4회 다시 본다(반영됨). 문장에 없는 전략 값(예: 볼린저 "하단 터치 인정 기간")을 되물으면 칩을 골라 `answers`에 넣고, 어떤 값을 골랐는지 글에 밝힌다.
- AI 리포트 생성은 모델 한도에 따라 끝나지 않을 수 있다 → `studio_record.mjs`는 `result.json`을 AI 단계 앞에서 먼저
  저장하고 AI 단계 실패를 치명으로 보지 않는다(3분 제한). 영상·기여도 사진에는 AI 리포트가 필요 없다.

## ④ 글 작성

형식은 [references/post_template.md](references/post_template.md). 수치는 **캡처·화면 텍스트에서 그대로** 옮기고,
파생 값(벤치마크와의 차이 등)은 계산을 다시 확인한다. 시작 멘트는 반드시
`<전략 이름> 전략을 백테스트 해봤습니다.`로 시작한다(2026-10-04 사용자 지정 — **속설 시리즈는 예외: 위 "글 형식" 참고**).

- 입력 문구·해석된 조건은 **사진이 아니라 텍스트**로 쓴다(사용자 지시). 결과 해석은 지표별로 자세히, 평가 어휘 없이.
- 280 가중 글자(한글 1자=2)를 넘으면 `--long`을 쓴다. 이 계정은 긴 글(note_tweet)이 API로 정상 게시된다.
- **AI 리포트 "핵심 요약"은 매번 첫 글의 답글로 잇는다**(2026-10-05 사용자 상시 지시 — 요청이 없어도 기본 동작). **속설 시리즈는 예외**(요약 본문 제외·답글 사진은 결과 페이지+매번 다른 항목 — 위 "글 형식" 4·5).
  결과 화면의 "AI 리포트" 탭에서 원문 그대로 복사하고, 다른 단락(개선 우선순위 등)은 올리지 않는다.
  첫 글을 올려 `POSTED_ID=`를 확인한 뒤 그 id로 `--reply-to`를 쓴다(미리보기에서 답글도 함께 보여 준다).

## ⑤⑥ 미리보기와 게시

- **게시 전 영상 방향 확인**(10-13 #8 실측): `ffprobe -v error -select_streams v:0 -show_entries stream=width,height:stream_side_data=rotation -of default=nw=1 <영상>` — 1920×1080에 `rotation=` 줄이 없어야 한다.
  QuickTime Player에서 회전(⌘L/⌘R)하면 닫을 때 **파일에 자동 저장**돼 가로 영상이 세로로 보인다(컨테이너가 `mp42`로 바뀌고 `rotation=-90`이 들어간다). 영상은 Quick Look(스페이스바)로 보거나 복사본으로 열게 하고,
  회전이 들어갔으면 작업 폴더의 원본(`final*.mp4`)을 다시 복사한다(회전 파일은 백업).

```bash
uv run python scripts/post_to_x.py --file post1.txt --long --image b.png --image c.png --image d.png   # 미리보기(기본) — 사진 3~4장
uv run python scripts/post_to_x.py --file post1.txt --long --image b.png --image c.png --image d.png --post     # 게시 → 마지막 줄 POSTED_ID=<id>
uv run python scripts/post_to_x.py --file post2.txt --long --image i_ai.png --reply-to <POSTED_ID> --post   # AI 핵심 요약 답글(+점수 카드)
```

- 글은 `--file`로 넘긴다(따옴표·줄바꿈 안전). 사진은 글당 최대 4장, PNG/JPEG 5MB 이하. 동영상은 `--video`(영상 모드).
- **글을 하나씩 올리고 성공(`POSTED_ID=` 출력)을 확인한 뒤 그 id로 다음 글을 올린다.** 한 줄로 이어 붙이지 않는다 —
  2026-10-04 사고: `$(...)` 연쇄에서 앞 글 실패가 가려져 id가 빈 채 넘어갔고, 뒤 글 2개가 단독 글로 올라갔다
  (스크립트는 이제 빈 `--reply-to`를 거부한다).
- 끝나면 API로 조회해(Bearer 토큰, `GET /2/tweets?ids=…&tweet.fields=note_tweet,attachments,referenced_tweets`)
  답글 연결·사진 수를 확인하고 링크를 보고한다. 임시 브라우저는 `pkill -f "node browser_server.mjs"`로 끈다.

## 환경 (값은 `.env`, 대화·출력·기록에 쓰지 않는다)

`X_API_KEY`·`X_API_SECRET`·`X_ACCESS_TOKEN`·`X_ACCESS_TOKEN_SECRET`(게시, OAuth 1.0a — 앱 권한 Read and Write로
발급해야 한다)·`X_BEARER_TOKEN`(조회). `X_OAUTH2_*`는 스크립트가 쓰지 않는다. 요금은 종량제(글·읽기 건당 과금)다.
`.env`가 없거나 키가 비면 스크립트가 변수 이름만 알리고 중단한다. 키가 대화에 노출됐다면 콘솔에서 재생성을 권한다.

절차가 바뀌면 `backend/tests/test_post_to_x.py`와 이 문서를 같이 고친다.
