# 백테스트 결과를 X에 올리기

흐름: **① 전략 문장 정하기 → ② 로컬 앱에서 백테스트 → ③ 사진 3장 캡처 → ④ 글 작성 → ⑤ 미리보기 → ⑥ 게시.**
게시는 공개·되돌리기 어려운 외부 전송이다. ⑤ 미리보기 없이 게시하지 않고, 사용자가 올리라고 한 글만 올린다.

## 먼저 지킬 것

- **규제 안전 원칙(CLAUDE.md)**: 글은 "백테스트 사례"다. "추천 전략", "유망", "지금 사야 할", 시장 전망,
  종목·전략 추천 표현을 쓰지 않는다. 결과는 과거 데이터 기준 수치로만 서술하고 평가·권유 어휘를 넣지 않는다.
- **대원칙 2**: 사용자가 정하지 않은 결정(어느 예시, 기존 글 삭제)을 대신 내리지 않는다.
  고르라고 한 경우에만 고르고, 무엇을 골랐는지 보고한다.
- **면책 문구는 넣지 않는다**(2026-10-05 사용자 상시 지시). "과거 데이터 기반 시뮬레이션 결과이며 미래 수익을
  보장하지 않습니다" 줄을 글에 넣지 않는다. 사용자가 다시 넣으라고 할 때만 넣는다.
- **인용(quote)·답글은 내가 쓴 글이나 나를 멘션한 글에만 API로 가능하다.** 다른 계정(정치인·뉴스 포함) 글은
  X가 403으로 거부한다(2026-10-04 실측). 그 글을 인용하려면 사용자가 X 앱에서 직접 해야 한다 — 사진·글
  문안만 준비해 준다. 기사 주소를 글 본문에 넣는 것은 가능하다(링크 포함 글은 건당 비용이 더 높다).
- **개선 우선순위·행동 제안은 올리지 않는다.** AI 리포트의 "개선 우선순위"는 사용자 행동 제안이라 규제 원칙과
  충돌한다. AI 리포트는 "핵심 요약"만 복사하고(2026-10-04 사용자 선택), 나머지는 먼저 묻는다.
- **기존 글을 수정·삭제하는 것은 사용자 몫이다.** X API로는 글 수정이 안 되고, 삭제도 요청 없이 하지 않는다.
  잘못 올린 글이 생기면 상태를 조회해 보고하고 처리 방법을 묻는다.

## ① 전략 문장

- "우리 예시"를 쓰라고 하면 `components/strategy/StrategyExampleTabs.tsx`의 `prompt`를 **글자 그대로** 입력한다.
  어느 예시인지 지정이 없으면 하나를 골라 이유와 함께 알리고, 첫 화면의 "예시로 시작해 보세요!" 카드가 무난하다.
- 테마어는 정본 카탈로그에 있는 이름으로 쓴다. 같은 뜻이라도 어휘에 따라 유니버스가 달라진다
  (2026-10-04 사고: "치킨"은 식품 업종 전체로 해석, 테마 "닭고기"·"육계"는 7~9종목). 입력 후 요약의
  **유니버스가 말한 대상과 일치하는지** 확인한다(`data/kg-theme-catalog.json`, `data/kg-naver-theme-catalog.json`).

## ② 백테스트 (로컬 앱, Playwright)

사전: 프론트(3000)·백엔드가 떠 있어야 한다. 임시 폴더에 Playwright를 설치한다(저장소 의존성 불변):

```bash
PW=<scratchpad>/pw; mkdir -p $PW && cd $PW && npm init -y >/dev/null && npm i playwright && npx playwright install chromium
cp /Users/eugene/nullalgo/simons/.claude/skills/x-backtest-post/scripts/*.mjs $PW/   # ESM은 node_modules 옆에서만 import가 된다
export GUEST_PW="$(python3 -c "import json;print([x for x in json.load(open('guest-accounts.local.json')) if x['guestId']=='guest_5312'][0]['password'])")"  # 저장소 루트에서. 값을 출력·기록하지 않는다
(nohup node browser_server.mjs > server.log 2>&1 &); sleep 15; cat server.log   # "ready"
```

- 로그인은 무기한 데모 게스트 `guest_5312`(id 50)를 쓴다. **로컬 `.env`가 운영 DB라 백테스트 기록이 운영 DB에
  이 계정 이력으로 남는다** — 사용자에게 알린다. 해석에는 OpenRouter 무료 한도가 쓰인다.
- 대화는 `node step.mjs type "<문장>"` → `wait 40` → `text`로 진행한다. 되묻기 카드는 칩을 `click`한다
  (예: "비중 조정", "손절 -15%", "최근 3년 데이터", "1,000만원", "이 전략으로 확정", "백테스트 시작하기").
  "직접 입력"을 누르기 전에는 입력창이 없는 카드가 있다.
- **새 대화는 깨끗해야 한다.** 이전 대화의 설정(리밸런싱·익절 등)이 이어진다 — `click "대화 종료"` 후
  `goto http://localhost:3000/analytics/new`. 이전 결과가 복원돼 입력창이 없으면 `click "결과 닫기"`.
- 예시에 없는 항목(리밸런싱·익절 등)은 가장 중립적인 값("안 함")으로 답하고 글에 밝힌다. 사용자가 값을 주면 그것을 쓴다.
- **해석 요약이 문장과 어긋나면 올리지 않는다**(예시에 없는 조건이 끼거나 "해석하지 못했어요"가 나옴).
  2026-10-04 "반도체 ETF 60일선 위 보유"가 "ETF만 대상으로"를 거래대금 조건으로 오해했다. 고치려 들지 말고
  증상과 트레이스(`backend/logs/agent_traces/<날짜>.jsonl`의 LLM span 모델명)를 사용자에게 보고하고
  `strategy-interpretation-fix` 스킬을 제안한다. 다른 예시로 바꾸려면 알린다.
- 이동평균 기간 등 문장에 없는 값을 널스탁이 정한 경우(예: "단기/장기" → 5일-20일·20일-60일) 글에 그 사실을 적는다.
- 결과가 나오면(`백테스트 완료 — … 수익률 …%`) 손실이어도 있는 그대로 올린다.

## ③ 사진 — 한 가지에 치우치지 않고 여러 종류를 쓴다 (2026-10-05 사용자 지시)

```bash
node capture.mjs <접두사>     # 결과 화면에서 → <접두사>_<코드>_<이름>.png 최대 9장(없는 섹션은 건너뛴다)
```

| 코드 | 내용 | 쓰임 |
|---|---|---|
| b_overview | 핵심 지표 + 수익 곡선 | **첫 글에 항상** |
| c_contrib | 종목별·섹터별 기여도 | 첫 글 기본 |
| d_dist | 거래 수익률·보유 기간 분포(막대) | 선택 |
| e_factor | 팩터 회귀(시장·규모·가치·모멘텀 베타) | 선택 |
| f_risk | 매매 회전율·VaR/CVaR·63일 롤링 샤프/베타 | 선택 |
| g_stocks | 종목 분석 탭 상단 10행 | 선택 — **종목 코드순 첫 10개라 대표성이 없다** |
| h_trades | 매매 기록 탭 상단 9행(매수·매도 사유) | 선택 — **가장 이른 거래 9건**이다 |
| i_ai | AI 리포트 점수 카드(점수·LEVEL·성장성/안정성/일관성) | **AI 핵심 요약 답글에 첨부** |
| a_strategy | '내 전략' 팝업 | 입력 문구·조건은 텍스트로 쓰므로 보통 안 붙인다 |

- **첫 글은 b + c에 더해 이번 결과에서 보여 줄 만한 사진을 1~2장 더 골라 3~4장을 붙인다**(글당 최대 4장).
  매번 같은 조합(b+c)을 반복하지 않는다 — d·e·f·g·h 중 이번 전략의 특징(거래가 잦다 / 손절 구간에 몰렸다 /
  특정 팩터 쏠림 / 보유 기간이 짧다 등)을 가장 잘 보여 주는 것을 고르고, **직전 글에서 쓴 조합과 다르게** 짠다.
  어떤 사진을 골랐고 이유가 무엇인지 미리보기 보고에 적는다.
- 붙인 사진이 다루는 수치는 해석 글에 **사진 속 값 그대로** 한두 줄 덧붙인다(평가 어휘 없이. 예: "거래 수익률 분포에서
  -15~-5% 구간이 212회입니다"). g·h 사진은 일부 행이라는 점을 글에 밝힌다("종목 코드순 상위 10개", "가장 이른 9건").
- AI 핵심 요약 답글(⑥)에는 `i_ai` 한 장을 붙인다.
2배 해상도(CDP `clip.scale`)라 파일당 50~280KB(한도 5MB). **캡처를 전부 열어 눈으로 확인**한다(툴팁·잘림·팝업 잔존·
상단 고정 바 겹침). 개요에서 스크롤해 찍는 사진은 스크립트가 고정 헤더를 숨기고 찍지만, UI가 바뀌면 다시 겹칠 수 있다.
백테스트 기록 페이지에서 지난 결과를 다시 열 때는 `click "백테스트 기록"` → 카드 클릭 → 캡처(어느 탭에서든 된다).

## ④ 글 작성

형식은 [references/post_template.md](references/post_template.md). 수치는 **캡처·화면 텍스트에서 그대로** 옮기고,
파생 값(벤치마크와의 차이 등)은 계산을 다시 확인한다. 시작 멘트는 반드시
`<전략 이름> 전략을 백테스트 해봤습니다.`로 시작한다(2026-10-04 사용자 지정).

- 입력 문구·해석된 조건은 **사진이 아니라 텍스트**로 쓴다(사용자 지시). 결과 해석은 지표별로 자세히, 평가 어휘 없이.
- 280 가중 글자(한글 1자=2)를 넘으면 `--long`을 쓴다. 이 계정은 긴 글(note_tweet)이 API로 정상 게시된다.
- **AI 리포트 "핵심 요약"은 매번 첫 글의 답글로 잇는다**(2026-10-05 사용자 상시 지시 — 요청이 없어도 기본 동작).
  결과 화면의 "AI 리포트" 탭에서 원문 그대로 복사하고, 다른 단락(개선 우선순위 등)은 올리지 않는다.
  첫 글을 올려 `POSTED_ID=`를 확인한 뒤 그 id로 `--reply-to`를 쓴다(미리보기에서 답글도 함께 보여 준다).

## ⑤⑥ 미리보기와 게시

```bash
uv run python scripts/post_to_x.py --file post1.txt --long --image b.png --image c.png --image d.png   # 미리보기(기본) — 사진 3~4장
uv run python scripts/post_to_x.py --file post1.txt --long --image b.png --image c.png --image d.png --post     # 게시 → 마지막 줄 POSTED_ID=<id>
uv run python scripts/post_to_x.py --file post2.txt --long --image i_ai.png --reply-to <POSTED_ID> --post   # AI 핵심 요약 답글(+점수 카드)
```

- 글은 `--file`로 넘긴다(따옴표·줄바꿈 안전). 사진은 글당 최대 4장, PNG/JPEG 5MB 이하.
- **글을 하나씩 올리고 성공(`POSTED_ID=` 출력)을 확인한 뒤 그 id로 다음 글을 올린다.** 한 줄로 이어 붙이지 않는다 —
  2026-10-04 사고: `$(...)` 연쇄에서 앞 글 실패가 가려져 id가 빈 채 넘어갔고, 뒤 글 2개가 단독 글로 올라갔다
  (스크립트는 이제 빈 `--reply-to`를 거부한다).
- 끝나면 API로 조회해(Bearer 토큰, `GET /2/tweets?ids=…&tweet.fields=note_tweet,attachments,referenced_tweets`)
  답글 연결·사진 수를 확인하고 링크를 보고한다. 임시 브라우저는 `pkill -f "node browser_server.mjs"`로 끈다.

## 환경 (값은 `.env`, 대화·출력·기록에 쓰지 않는다)

`X_API_KEY`·`X_API_SECRET`·`X_ACCESS_TOKEN`·`X_ACCESS_TOKEN_SECRET`(게시, OAuth 1.0a — 앱 권한 Read and Write로
발급해야 한다)·`X_BEARER_TOKEN`(조회). `X_OAUTH2_*`는 스크립트가 쓰지 않는다. 요금은 종량제(글·읽기 건당 과금)다.
`.env`가 없거나 키가 비면 스크립트가 변수 이름만 알리고 중단한다. 키가 대화에 노출됐다면 콘솔에서 재생성을 권한다.

## 끝낼 때

게시한 글 링크·결과 한 줄·남은 정리(중복·잘못 올린 글, 운영 DB에 남은 기록)를 보고한다. 스크립트나 이 스킬의
절차가 바뀌면 `backend/tests/test_post_to_x.py`와 이 문서를 같이 고친다.
