# ⚠ 2026-10-13 사용자 결정: 속설 영상은 목소리 대신 "BGM + 자막"이 기본이다

#8에서 목소리(Gemini TTS)를 입혀 봤으나 반려됐다(치지직 노이즈·싱크 불일치) — "말을 넣는 대신 어울리는 BGM을 넣고 자막이
설명을 대신하는 것으로 하자". **기본은 아래 BGM+자막이고, 목소리는 사용자가 다시 요청할 때만 아래 절차를 쓴다.**

## BGM + 자막 방식 (기본)
- BGM: **기본은 밝은 곡 `scripts/cf/bgm_bright.py`**(사용자 요청 10-13 — 100BPM, C–G–Am–F 장조, 맑은 벨 플럭+패드+아주 가벼운 킥·셰이커). 차분한 대안 `scripts/cf/bgm_calm.py`
  (84BPM Am–F–C–G, 드럼 없음). 둘 다 저작권 없는 자체 합성. 밝기 지표(스펙트럼 무게중심): 밝은 곡 585Hz / 차분한 곡 147Hz.
  `uv run --with numpy python bgm_bright.py out.wav <총길이> <본편 시작> <아르페지오 시작(④ 칩)> <촘촘해지는 시작(⑥ 실행)> <결과 시작> <끝 카드 시작>`.
  홍보 CF용 `cf_music.py`(킥·클랩·충격음)는 설명 영상에 과해서 쓰지 않는다.
- 믹스: 2패스 `loudnorm(linear, I=-17(밝은 곡)/-18(차분한 곡), TP=-3)` → `alimiter` → AAC 48kHz. 확인: 피크 -3dBFS 이하.
- **자막 문구는 실제 화면과 맞아야 한다**: 해석 결과는 카드가 아니라 채팅의 항목별 정리 목록이다 — ③은 "널스탁이 해석한 전략을 항목별로 정리해 줍니다"(`make_plan.py` CAPTIONS, 10-13 사용자 지적). 시청자 문구(자막·게시글)에서 "카드"라고 부르지 않는다(끝 카드는 실제 카드라 예외).
- 자막이 설명을 대신하므로 **각 단계가 읽을 시간만큼 보여야 한다**: ② 해석 대기 4.7초(×1.2, 진행 표시 "분석 중…·파싱 중…" 보이게) /
  ③ 해석 카드 6초 정지 / ④ 칩 1배속(칩당 약 2.7초)에 **자막에 항목과 정한 값만 적는다**("④ 익절 — 안 함", "④ 하단 터치 인정 기간 — 10거래일" — "문장에 없던 값은 버튼으로 답합니다" 같은 안내 문구는 쓰지 않는다, 10-13 사용자 지시; `meta.json`의 `chip_captions`로 지정) /
  ⑥ 실행 ×6 / 결과 지표 3.5초·벤치마크 4초. 총 약 55초.
- 구현 예: `references/bgm_build_example.py`(이 녹화의 클립 번호가 박혀 있다 — 자막 문구·속도 조정 + 렌더 + BGM 생성 + 믹스).
- 편집 계획 도구(`make_plan.py`) 교정 2건(10-13): ② 해석 대기 구간이 "대화 기록 닫기" 클릭이 늦으면 0.7초로 줄던 것 → 전송 직후부터 최소
  `2×WAIT_TARGET_SEC` 확보 / ③ 해석 카드 6초 창이 첫 칩 클릭까지 품어 ④에서 같은 클릭이 반복되던 것 → 첫 칩 접근 직전까지만 쓰고 천천히 늘림.
- 게시 문안에 목소리·"배경 음악" 언급을 넣지 않는다(영상만으로 충분).

# (참고) 목소리(내레이션) 입히기 — 사용자가 다시 요청할 때만

목소리는 Gemini TTS(`scripts/cf/cf_tts_gemini.py`, 음성 Charon, `.env`의 GOOGLE_API_KEY)로 만든다. **대본 문구만 Google로
전송된다**(홍보 CF와 같은 방식). 무료 한도는 **모델별 하루 10건**이라 줄 수를 8줄 안팎으로 잡고, 대본을 고치면 한 편 전체를
다른 모델로 다시 합성해야 한다(한 편에서 모델이 섞이면 목소리가 달라진다). 소리는 직접 못 듣는다 — 받아쓰기로 검수하고
사용자에게 들어 봐 달라고 한다.

## 순서

1. 평소처럼 녹화·검증·`studio_build.sh` → `plan.json`의 장면 구성을 확인한다(자막 ①~⑦, 칩 클릭 수에 따라 클립 번호가 달라진다).
2. **대본 8줄**(장면 설명 + 화면에 보이는 수치만, 평가·권유·면책·"빨리 감았다" 표현 금지, 숫자는 TTS가 읽게 한글로:
   "마이너스 칠십육 점 육 삼 퍼센트"). 줄 배치: 제목·입력 / 해석 카드 / 칩 답변(칩 클릭 순서대로) / 확정 / 실행 / 결과 지표 /
   벤치마크 / 끝 카드.
3. 합성: `CF_TTS_MODEL=gemini-3.8-flash-tts uv run python scripts/cf/cf_tts_gemini.py vo Charon "L1=…" "L2=…" …`
   → `vo/L1.wav`… 줄 길이는 예상보다 길다(약 4~5음절/초, 8줄 합계 약 54초).
4. **영상을 줄 길이에 맞춘다**(줄을 줄이면 TTS 한도를 또 쓴다). `plan.json`의 클립 `speed`만 바꾼다 — 줌 카메라(`shots`)는
   녹화 시계 기준이라 어긋나지 않는다. 해석 카드 클립은 줄 길이로 늘리고, 칩 클립은 1배속, 확정·실행 클립은 줄 길이에 맞춰
   비례 조정하고(배지 "빨리 감기 ×N"도 갱신), 벤치마크 장면과 끝 카드를 마지막 줄까지 늘린다. 그 결과 약 56초(기준 45~70초).
   `render_studio.py plan_vo.json final_silent.mp4`로 다시 렌더.
5. 줄 시작 시각은 장면 시작 + 0.2~0.4초이고 앞 줄이 끝난 뒤 0.1초 이상 간격을 둔다(겹침·영상 길이 초과를 코드로 확인).
6. 믹스(영상 스트림 복사, 음성만 AAC):
   `adelay`로 줄마다 지연 → `amix=normalize=0` → `loudnorm=I=-17:TP=-3:LRA=11` → `apad=whole_dur=<영상 길이>`.
   확인: `ffmpeg -i out.mp4 -af ebur128=peak=true -f null -` → 약 -17 LUFS, 피크 -3 dBFS 안팎.
7. **받아쓰기 검수**: `python3 scripts/cf/cf_vo_check.py vo/L1.wav … vo/L8.wav`(대본과 다른 줄만 고친다. 숫자·띄어쓰기 표기 차이는 무시).
8. 접촉 시트(`ffmpeg … fps=1/3.5,tile`)로 장면 흐름을 본다. 게시 전에 사용자에게 목소리를 들어 보게 한다.

## 함정
- 말투 지시문을 합성 문장에 넣지 않는다(지시문까지 소리 내어 읽는다 — 홍보 CF 10-12 실측).
- 분당 한도(429)는 `cf_tts_gemini.py`가 재시도한다.
- AI 리포트 생성은 한도로 3분 안에 끝나지 않을 수 있다(10-13 #5·#8) — 영상에는 필요 없다.

## 2026-10-13 #8 실측 교정 — 첫 버전은 "치지직 노이즈 + 싱크 불일치"로 반려됐다

**싱크가 어긋난 원인과 방법(위 4번을 대체한다)**
- 원본 녹화에서 해석 카드가 나온 뒤 약 0.9초 만에 첫 칩 클릭이 시작된다. 표준 편집의 해석 카드 장면(6초)이 그 클릭과 두 번째
  칩까지 포함해서 칩 클립이 같은 클릭을 한 번 더 보여 준다 → 말(줄 단위)이 화면보다 최대 4초 늦는다.
- **줄 단위가 아니라 문장 단위로 맞춘다.** 줄을 무음 구간(`silencedetect=noise=-38dB:d=0.12`)에서 문구로 쪼개고, 각 문구를
  화면 이벤트에 맞춘다: 해석 카드 장면은 첫 칩 클릭 직전까지만 쓰고(`clip3.to = clip4.from`) 문구 길이만큼 늘린다 / 칩 문구는
  **누르는 순간에 끝나게** 시작 시각을 잡는다(`시작 = 누른 시각 − 클립 시작 + 0.3 − 문구 길이`) / 문구보다 클립이 짧으면 클립만 늘린다.
  구현 예: `references/voice_build_example.py`(이 녹화의 클립 번호·자르는 시각이 박혀 있다 — 방식만 가져간다).
- **무음 자동 제거를 믿지 않는다.** TTS 쉼 구간에 -45dBFS 안팎의 잡음 방울이 있어 `silenceremove`가 쉼을 못 지운다(문구가 2배로
  길어졌다). 무음 탐지로 얻은 정확한 구간을 `-ss/-to`로 자르고 짧은 페이드만 건다.

**잡음 — Gemini TTS 원본 자체가 거칠다(측정)**
- 지표: 3.5~11kHz 대역(고역 통과 2단+저역 통과 2단)을 8ms 창으로 나눠 `최대/RMS(크레스트)>5`인 창 수. 초당: Gemini 원본 22.4 →
  클릭 제거·70Hz/10kHz 필터 12.5 → **가파른 7kHz 저역 통과(`lowpass=f=7000`×3) + `adeclick` 5.5** → macOS Yuna 1.8.
  (12.5kHz 이상 에너지 지표는 리샘플러 영향이 섞여 쓰지 않는다. 믹스·loudnorm·AAC 단계에서는 늘지 않는다.)
- 후보를 둘 만들어 사용자가 듣고 고르게 한다: A=Gemini(7kHz 필터, 약간 먹먹할 수 있음) / B=`say -v Yuna -r 180`(깨끗하지만 기계적,
  외부 전송 없음, 한도 없음). 소리는 제가 못 들으므로 이 지표는 참고일 뿐이다.
- **믹스는 loudnorm 단일 패스를 쓰지 않는다**(피크가 +0.4dBFS까지 올라 클리핑). `amix` → 2패스 `loudnorm(linear=true, I=-17, TP=-3)` →
  `alimiter` → `aresample=48000`. 확인: 피크 -3dBFS 이하.
