# 사고 기록

사고 한 건 = 파일 한 개. 틀은 `docs/incidents/_template.md`(결론 한 줄 / 증상 / 원인 / 해결 / 재발 방지 / 재발 이력 / 한 줄로).

## 절차

1. **기존 기록부터 찾는다.** `docs/incidents/`에서 같은 증상이 있는지 본다. 있으면 새 파일을 만들지 않고
   그 파일의 `재발 이력`에 날짜·상황 한 줄을 추가하고 Status를 `recurred`로 바꾼다. 그 뒤 이전 `재발 방지`
   장치가 왜 못 잡았는지를 `원인`에 덧붙인다.
2. 없으면 `docs/incidents/<YYYY-MM-DD>-<slug>.md`를 템플릿으로 만든다(slug는 소문자 영문·하이픈).
3. 증상·원인은 **확인한 것만** 단정한다. 트레이스·로그·코드로 확인하지 않은 원인은 "추정"이라고 쓴다.
4. 해결에는 커밋 해시를 쓴다. 미커밋이면 "미커밋"이라고 쓰고, 커밋 뒤에 해시로 갱신한다.
5. 재발 방지에는 실제로 존재하는 고정 장치의 경로(테스트·훅·게이트)만 쓴다. 없으면 "없음"과 이유를 적는다.
   버그를 고쳤는데 회귀 테스트가 없다면 이 칸이 그 누락을 드러낸다.
6. 본문은 CLAUDE.md의 설명 스타일(결론 먼저, 번호 단계, 비유 먼저·용어 병기)을 따른다.
7. 사용자가 읽고 고친 뒤에만 Status를 `fixed`로 바꾼다. 커밋은 사용자가 지시할 때만 한다(경로 명시 스테이징).

## 규칙

- 사용자가 말하지 않은 원인·해결을 지어 채우지 않는다.
- 규제 안전 표현 금지 규칙은 기록 문서에도 같다(추천·전망 표현 금지).
- 기존 사고를 소급해 옮기는 일은 사용자가 요청한 건만 한다(메모리 파일을 임의로 일괄 변환하지 않는다).
